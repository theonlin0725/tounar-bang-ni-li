# 邮件管理与手动自测交付说明（2026-10-30）

## 已有能力与本次补齐

原有登录 OTP、手动补录产生通知、候选筛选、定时／CLI 摘要发送和只读摘要预览继续保留。本次新增管理员模板／约束编辑、版本恢复、隔离 HTML 预览、有限收件人模板试发、从本人台账选择记录的独立测试批次、统一投递审计，以及保留数据和模板版本的专用启动器。

真实通路由用户执行，入口和详细步骤见 [自测指南](MAIL-SELFTEST-GUIDE.md)。准备工作没有触发真实 SMTP 邮件，也没有用模板试发冒充真实业务触发。

## 权限与隔离

普通服务的管理员、测试收件人、业务测试和本机自测登录配置默认关闭／为空。专用 `mail:selftest` 启动器使用 `data/mail-selftest-profile.json` 固定的 `data/mail-selftest/` 副本；管理员按 `ADMIN_EMAILS`（未配置时回退登录白名单第一项），测试收件人使用显式配置或本机登录白名单；启动输出清楚列明。网页不能扩权。业务测试仅访问本人台账并限制到配置的测试收件人，独立批次不消费正式通知或回看频控。所有试发固定添加自测主题标识，最多 5 次／分钟，发送重试使用相同幂等标识。

自测副本已从旧验收库恢复，保留 40 条台账和原插件设备绑定；启动前校验 profile 身份、数据库身份以及预期设备未撤销／未过期／账号未删除，失败即停止，不会重新复制或回退旧基线。`mail:selftest` 还设置 `ENABLE_SELFTEST_LOGIN=true`：只对开发模式、回环地址、`http://127.0.0.1`/`localhost`、且在 `ADMIN_EMAILS` 和 `ALLOWED_EMAILS` 中的邮箱回显 OTP，不发送邮件；普通 `npm start`/生产默认关闭。每次仍走 OTP 限流和尝试次数，审计记录 `auth.selftest_otp_issued`，生产禁止开启。

预览 HTML 通过需管理员会话且绑定当前用户的短时地址提供，5 分钟过期；最多保留 100 份内存预览，不落盘。在 sandbox iframe 内允许安全内联排版，禁止脚本、外部资源和表单。普通动态变量先转义，原始 HTML 变量限于声明的安全片段；保存和渲染时均校验。核心变量在纯文本及 HTML 中均保留。正文和实际 OTP 值不写投递日志。数据删除会清除相应用户的新增测试／投递日志并匿名化模板版本作者。

SMTP 明确接受目标收件人才记 accepted；拒收记失败，超时／中断保守记未知。没有送达 Webhook 或已读追踪，所以不能自动证明最终收件箱收到。

## 持久化与版本

`mail_template_versions` 保存不可变版本和示例变量，最新版本生效；保存执行预期版本比较。恢复历史版本会追加版本而非重写历史。`mail_test_runs` 保存触发请求摘要 hash 和结果，`mail_deliveries` 记录渠道、版本、关联批次、服务商邮件 ID 及安全失败说明。新增表与列均是增量迁移。

模板／业务改变后要求重新预览。正式摘要和业务测试共享候选、卡片、外壳渲染和发送。业务测试跳过定时时间窗口、按所选记录筛选并不消费正式通知；不代表每日 08:00 调度、QQ IMAP 或线上发布验收。

## 验证边界

- 后端回归 `npm test`：包含管理员角色、白名单、约束、版本、缺失策略、转义、真实台账输入、幂等与 SMTP 接受／拒收／超时的本地模拟。
- 原网页回归 `npm run test:web`：隔离 SQLite／outbox。
- 新入口 `npm run test:mail-admin`：实际浏览器编辑、保存生效、恢复、错误反馈、业务触发、权限拦截、预览内联排版和窄屏。
- 所有验证使用本地 outbox 或模拟 SMTP；真实收件箱、邮箱客户端排版与自动调度由用户另行验收。

已有未提交的模块化调整保留，没有提交、发布或改动原真实数据库。
