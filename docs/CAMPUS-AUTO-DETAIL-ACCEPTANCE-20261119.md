## 1. 可复跑纯自动路径

命令：

```bash
npm run test:campus-live -- --company=得物

```

测试做的事：

1. 启动隔离本地后台，正常登录/配对；
2. 打开 CSV 的校招入口；
3. 只通过页面可见链接/导航/岗位卡片点击，不发送 `capture_current_tab`、不直接调模型、不伪造事件；

5. 从 SQLite 核验 `events.job_viewed`、`application_field_sources.jd_text=model_source_quote`；
6. 打开真实前端 `/?app=<id>` 核验整理版 JD。

## 3. 代码修复

### 3.1 页面稳定判断（核心）

`extension/content/tracker.js`：

- 新增 `findJobPanel()` / `panelText()` / `panelScore()`：只取当前可见岗位面板，排除导航、推荐区、表单和全局 header/footer。
- 新增 `stabilityText()` / `panelSnapshotFor()`：以“岗位身份 + 规范化正文”判断稳定；全页时钟、轮播、公告不再拖住模型。
- `detectJob()` 改为 `MODEL_STABLE_MS=1200` 的面板稳定窗口；`modelCandidate()` 350ms 节流，避免高频扫整页。
- `detectAndTrackRoute()` 去掉 `lastDomChange < 800` 的全页门槛，改为新路由首帧 300ms + 面板稳定。
- `tickDwell()` 使用 `panelReadyAt`，岗位面板稳定后正常累计可见停留，全局动画不再阻止 3 秒入账。

### 3.2 快速切岗与重复结果

- 请求签名绑定 URL + 岗位身份 + 正文版本；响应回来时重新计算当前面板签名，签名不一致直接丢弃。
- 同 URL 抽屉切 A→B：A 未返回时切 B，A 结果不会写进 B，B 会重新请求并单独入账。
- `contentIdentity` 纳入标题、公司、JD、地点、site_job_id、URL；同一标题不同岗位也会被识别为新版本。
- 失败时只做一次短退避重试；明确拒绝/不完整不重试，规则兜底保留。

### 3.3 授权提示

- 后台 `captureTab` 在缺权限时返回具体 host：`该站点未授权（host）。请在“数据与授权”中授权最终详情域名后重试`。
- `jd_model_extract` 缺权限时同样提示当前 host；便于从自建入口跳到北森/hotjob/Moka/飞书后补授权。

### 3.4 负例

`tests/e2e/panel-stability.mjs` 覆盖：

- 全页时钟持续更新：仍按岗位面板自动入账，模型只调用 1 次。
- 列表与详情并排：模型输入只含当前岗位，不含推荐岗位/列表。
- 同 URL 抽屉 A→B：A/B 各自入账，不串。
- A 模型未返回即切 B：A 不写 B，B 不漏记。
- 列表页：零模型请求、零入账。

## 6. 跨域授权边界（必须明说）

本轮 `campus-auto-live` 覆盖运行使用测试扩展预授权本次清单域名，目的是把“详情识别/模型/台账/前端”与“Chrome 原生授权弹窗”分开验证；**这部分不能算真实跨域授权通过**。

真实链路的代码和提示已补齐，但 headless Chromium 不能代替用户点击 Chrome 原生“允许”弹窗。跨域样本需要：

1. 只授权自建校招入口；
2. 点击岗位跳到北森/hotjob/Moka/飞书；
3. 后台/网页提示需要授权的最终 host；
4. 用户在“数据与授权”里补授权；
5. 回到岗位，等待插件自动整理。

这一步保留为下一轮人工/有头浏览器验收项；在没有真实补授权的情况下，报告不虚增跨域通过数。

## 8. 仍缺什么

1. 130 家中 104 家没有可用详情样本；需要下一轮逐家点击/登录，才能把“3/130”提高。
2. 字节入口的“2027届校园招聘”项目筛选没有稳定自动点击；产品端不影响用户手动点。
3. 跨域补授权的 Chrome 原生弹窗需要真实用户手势/有头浏览器验收。
4. 安永、玛氏是项目/公告类页面，模型拒绝时保留规则原文，不应强行按单岗位整理。
