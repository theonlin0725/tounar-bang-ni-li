## 3. 本次截图问题：已确认到哪一层

### 3.1 浏览记录错误进入「待确认」

**用户实测**：卡片显示“浏览线索缺少可用于识别的公司、岗位或稳定标识”，分类为“字段待补充”；另有“只有公司+岗位候选，不能自动合并”。

**当前代码确认**：`server/src/domain/applications.js` 的 `processView()` 会把公司/岗位/稳定标识不足的事件送到 `VIEW_FIELDS_INCOMPLETE`；仅公司与岗位命中候选时也可能走 `COMPANY_TITLE_ONLY`。这些路径没有建立新的未投递业务记录。

前端「看过没投」读取的是 `applications` 中 `has_applied=0` 的记录，不会自动显示停留在 `review_items` 的事件。因此，这一问题涉及入账规则和不完整岗位表示，不能只改 Tab 名称或前端过滤条件。

**尚未确认**：未逐条读取截图对应的真实事件，不能断言每条都是哪家网站、哪个提取字段失败，也不能把全部复核项直接迁走。接手应按原事件定位，再恢复可识别的普通浏览记录。

### 3.2 展开后缺少页面/邮件证据

**用户实测**：无法从「查看邮件 / 页面证据」看到需要判断的数据。

**当前代码确认**：

- `web/assets/js/views/reviews.js` 只渲染 `subject_excerpt`、`from_domain`、`body_excerpt`、`status_text` 及收信日期。展开面板本身不会再读取来源事件或原信内容。
- 插件普通浏览的 `reviewForEvent()` 只保存证据等级、代码、站点、时间、状态文字、URL origin 等；通常没有邮件摘要和状态文字，也没有把岗位 JD/完整链接呈现给这个面板。
- `reviewList()` / `reviewDetail()` 主要返回复核证据 JSON 并关联收信日期，没有在此补出页面原文或邮件正文。
- 邮件当前仅保存有限摘要；`publicEvidence()` 在正文模式下最多保留 300 字片段，邮件头模式不提供正文。当前不能承诺每封历史邮件都有完整正文可以展开。

**结论**：已确认存在让页面证据区无内容可显示的结构性缺口。邮件问题还需区分未授权正文、未保存、关联缺失和界面缺字段，不能一概称为同一个故障。修复应覆盖存储/API/前端，并对无法恢复的历史内容明确说明。

### 3.3 「已笔试 / 已面试」不能只看一个状态值

已有 `assessment` 和 `interview` 状态，但“收到邀请”“已安排”“已经完成”不是同一件事。新需求必须补充阶段内状态及证据校验，同时保持已有笔试/面试历史可见。旧文档中的拆分、轮次约定见 [邮件阶段规则](MAIL-STAGE-RULES.md)，不得因整理新界面而静默丢失历史。
