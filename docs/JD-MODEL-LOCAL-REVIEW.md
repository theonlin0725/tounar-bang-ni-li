# JD 模型识别：调用门槛、成本与本地验收（2026-11-18）

分支：`codex/model-gated-local-review`，基于 `yuyiran/plugin-pairing-permissions`。
本轮只处理“模型读取页面信息前的判断规则”，额度与发布策略不在本轮范围。

## 本轮要解决的风险

插件获得某站点授权后，原实现会把“看起来像岗位详情”的页面正文交给大模型。若判断过宽，列表页、个人资料、申请记录、消息页等敏感内容也可能被上传；若判断过窄，跨站岗位又识别不到。

本版把判断拆成三层，任何一层不通过都不调用模型、不写台账：

1. **本地页面门槛**：在浏览器里先判断“这是不是单个岗位详情”，不通过就不发送。
2. **模型提示词**：要求模型对列表、主页、登录、简历、申请记录、推荐职位等一律返回 `is_job=false`；不确定也按 false。
3. **服务端校验**：模型结果必须通过原文逐字校验、段落引用校验和“至少一条职责或要求”校验，否则报错并保留原记录，不生成假岗位。

## 本地页面门槛（发模型之前）

按顺序检查，命中任一“不发送”条件就停止：

1. **连接与授权**
   - 插件已连接账号、未暂停采集。
   - 当前标签页是顶层窗口，不是后台页面或 iframe。
   - 当前站点已在插件里获得浏览器权限；未授权站点直接拒绝。
   - 帮你理自身页面不采集。
   - 网页主动连接只接受官方域名，或与插件当前后台完全同源；其他 localhost 端口不能发起绑定。

2. **路径**
   - 不发送：登录/注册、个人资料、简历、账号、消息/聊天、搜索、列表、投递记录、申请、设置、通知、收藏、面试、offer、用户主页等路径。
   - 不发送：`/jobs`、`/positions`、`/job-search`、`/recruitment` 这类列表落地页。
   - 仍可发送：`/jobs/123`、`/job/123` 这类单个岗位详情；URL 查询串里出现 `search` 不会误伤详情页。

3. **页面结构**
   - 只读取主内容区（岗位详情容器、`main`、`article` 等）的可见文本，不读取 `script/style/nav/header/footer/aside/form/input/textarea/select/contenteditable/button`。
   - 必须只有一个岗位标题（`h1` 或岗位标题类名），标题 2–120 字，且不是“职位/岗位/招聘/搜索结果/个人中心”等泛标题。
   - 必须出现“岗位职责/工作职责/职位描述/工作内容”或“任职要求/任职资格/职位要求/岗位要求”等章节标记（中英文均支持）。
   - 未知站点还必须满足以下之一：
     - 页面有 `JobPosting` 结构化数据；或
     - 同时出现职责、要求、申请入口三种信号。
   - 已有站点适配规则能明确识别出岗位时，视为本地强证据，可进入模型；仍受上面的路径、页面状态和授权限制。

4. **页面状态**
   - 职位已过期、已下线、不存在、关闭招聘、访问异常、安全验证等页面不发送。

5. **内容与隐私**
   - 不读取表单输入、密码、Cookie 或登录凭据。
   - 发送前把邮箱和手机号替换为 `[联系方式已省略]`。
   - 单页最多 30000 字符；超过不静默截断，提示用户打开单个岗位详情。
   - 页面安静 1.5 秒后才判断；同一 URL + 同一正文只调用一次；SPA 只换 URL 没换内容时不调用，避免把旧内容算到新岗位。
   - 同一账号、模型、完整 URL 和正文的重复请求命中 24 小时缓存，不重复计费。

## 模型侧规则

提示词现在明确要求：

- 只有“单个岗位详情 + 明确岗位名称 + 至少一条职责或任职要求”才返回 `is_job=true`。
- 列表/搜索结果、公司或团队主页、登录或安全验证、个人资料/简历/申请记录/消息、推荐职位、职位资讯，以及信息不足的页面，一律 `is_job=false`。
- 不确定时按 `false`，不得根据网址或域名猜岗位或公司。

服务端二次校验：

- `is_job` 必须是 `true`。
- 岗位名、公司、城市、批次必须是原文逐字片段；公司可以来自网页标题，但不能从域名猜。
- 每个职责/要求条目必须引用真实存在的段落或原文片段，不能改写。
- 至少一条岗位职责或任职要求，否则拒绝。
- 失败不落库、不覆盖原记录，也不会回退成规则生成的假岗位。
- 模型只整理 JD 字段，不能修改投递状态、是否投递、投递时间等事实。

## 权限与披露

- 网站授权卡片和 Chrome 权限确认框都明确提示：启用智能识别时，疑似单个岗位详情的可见正文会经帮你理后台发送给模型服务；表单输入不会发送。
- 插件后台在每次模型请求前再次校验设备令牌、采集开关和当前站点权限。
- 网站授权仍由用户逐站点确认；预选字节跳动不会自动申请浏览器权限。

## 额度与成本

模型选择：岗位提取和已有 JD 整理都属于结构化提取，使用 `deepseek-flash`；网页排版、插件安装检测、网站授权、列表页采集不调用模型。

两次真实 DeepSeek Flash 调用（合成岗位文本，不是账户账单）：

| 任务 | 输入/输出 token | 总 token | 非高峰估算 | 高峰估算 |
| --- | --- | ---: | ---: | ---: |
| 新岗位页面提取 | 533 / 85 | 618 | $0.000131 | $0.000262 |
| 已有 JD 整理（缓存命中 256） | 495 / 77 | 572 | $0.000083 | $0.000166 |

- 单账号默认每日最多 100 次模型尝试；命中缓存、表单排除、非岗位页拦截均不消耗调用。
- 按上表粗算，100 次新岗位提取的非高峰成本约 $0.013；这是按官方单价计算的估算，不是账单实扣。
- 价格依据：https://api-docs.deepseek.com/quick_start/pricing/

## 本地部署

本次已构建本地插件包并启动独立验收服务：

- 网页：`http://127.0.0.1:4310`
- 插件包：`web/downloads/bangnili-extension-0.2.8.zip`（SHA-256 `7a23891bc22290d39de60f82dacc62b72fdb375a762e3a667185294548cbc7ce`；解压后加载 `bangnili-extension` 目录）
- 数据：从本机真实库复制到 `~/tounar-acceptance/20261117-164630/`，不读写原库；发信为 `outbox`，不会真发邮件。
- 模型：`JD_AI_ENABLED=true`、`JD_AI_MODEL=deepseek-flash`，密钥只在启动进程中，不写入仓库、插件包或验收清单。
- 停止：`npm run local:stop -- --port 4310`

复现命令（密钥从原项目 `.env` 读取，不打印）：

```bash
JD_AI_ENABLED=true \
JD_AI_API_KEY="$(awk -F= '/^AI_API_KEY=/{print substr($0,index($0,"=")+1)}' "$HOME/Desktop/opencode project/帮你理/.env")" \
JD_AI_MODEL=deepseek-flash \
npm run local:acceptance -- --port 4310
```

插件安装：Chrome 扩展管理页 → 打开开发者模式 → 加载已解压的扩展程序 → 选择解压后的 `bangnili-extension` 目录；先停用旧插件，回到网页刷新并登录，按弹窗确认连接，再到“数据与授权”授权具体招聘网站。

自动连接修复：0.2.8 修正了带端口的权限匹配问题，恢复“已安装，刷新页面重新检测”，并保留手动配对码兜底。若刷新后仍提示未检测到插件，打开插件栏点「连接帮你理账号」，把 8 位配对码填到「数据与授权 → 插件绑定」；这条路径不依赖网页桥接。详见 `docs/PLUGIN-ACCESS-REVIEW.md` 的“v0.2.8 自动连接修复与手动配对兜底”。

## 已知边界

- Chrome 原生权限提示的“允许/拒绝”仍需人工点击；无界面自动化只能验证请求确认框、取消和授权统计。
- 26 个站点快照是离线页面，不代表当前线上页面；上线前仍需真实站点抽测。
- 费用是按 token 和官方单价的估算，不是 DeepSeek 账单凭证。
- 模型结果无法保证语义分类 100% 正确；原文引用校验只保证“没有编造和改写”，最终以人工核对为准。
