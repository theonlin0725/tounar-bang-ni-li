# JD 模型分类（本地待验收）

本版上传个人分支供小组审核，不合并、不部署。独立 JD_AI_* 配置只用于岗位采集，不改变邮件/进展 AI 配置。个人密钥在被 Git 忽略的 .env 中，插件包不包含密钥。其他成员需自行设置本机密钥并构建插件。

## JD 采集工作流与整理规则

流程直接写在代码中，不依赖 Dify：读取授权网页原文 → 模型识别岗位及分类 → 原文引用校验 → 原有队列上传入账 → 网页展示。

1. 读取可见正文和页面标题，不读取表单输入或 Cookie。
2. 模型区分单个岗位详情与列表、登录页、导航及推荐岗位。
3. 提取名称、公司、城市、招聘批次；仅使用原文明确信息，缺失留空。
4. 不同网站栏目统一为团队介绍、岗位职责、任职要求、其他信息，正文保留原文措辞。
5. 模型返回段落引用，服务端校验原文；失败不覆盖原记录。校验无法保证语义分类绝对正确。
6. 团队介绍合并连续语句；职责/要求逐条展示，有编号保留编号，无编号使用圆点；其他简短属性横排，缩写和相邻部门名合并展示，窄屏自然折行。排版合并使用标点判断，未追加模型调用。
7. 此流程仅整理岗位信息，不判断是否投递，不修改投递状态。缓存、额度和超时限制见下文。

## 行为

- 插件 0.2.6 从当前已授权页面读取可见文本和网页标题，不读取输入框、表单、Cookie。启用模型模式后，岗位名称/公司/城市/JD 分类不使用逐公司选择器或学习模板；旧规则仅供未启用模型的部署保持兼容。
- DeepSeek 非思考模式判断是否为单个岗位，输出字段及段落引用。服务端校验引用确实在原文中，不让模型重写正文。原文证据校验不能保证语义分类绝对正确。
- 统一栏目为团队介绍、岗位职责、任职要求、其他信息；正文条目独立展示。详情不重复展示摘要/全文，内部字段来源和变更字段名不在普通界面显示，后台历史仍保留。列表的简短预览和人工纠错表单不改。
- 旧记录不批量调用；用户点“整理岗位内容”才整理已有正文，保持岗位名、状态、投递事实及链接不变。版本冲突或人工修改的正文会阻止覆盖。
- 没有模型结果就不创建假岗位。错误不会回退为规则生成的记录；旧记录失败保留原内容。重新采集需要在原网页刷新/重试。
- 内存缓存按账号、模型、完整网址和原文隔离，24 小时、最多 200 项，合并并发重复请求；服务重启后清空。单个账号默认每日最多 100 次模型尝试（同样为进程内计数），不自动重试付费请求。单页 30000 字符上限，超限不静默截断，25 秒请求超时。
