## 3. 首轮基线暴露的问题与修复

首轮真实模型运行（同一语料，`clearProgressAuto` 和改期修复前）召回率为 74.2%，未达到门槛。失败归因集中在两类：

1. **可选字段缺失导致清晰进展误进待确认**：多封明确“邀请完成测评/面试”的邮件，因为正文没有截止时间、申请编号或具体地点，judge 的 `evidence_support` 偏低，被 `AI_PROGRESS_UNCERTAIN` 拦截。
   - 修复：对 `applied / assessment / interview` 三态，只要公司/岗位、阶段置信度和实际进展达标，即使缺少可选字段也自动入账；用户人工字段保护、终态保护和歧义归属规则不变。
2. **面试改期被规则分类器误判为拒信**：正文“如该时间不合适，请联系 HR 改期”命中“不合适”拒信词。
   - 修复：分类器识别改期/时间调整语境，排除拒信判定；模型仍可覆盖为 `interview`，状态机按面试阶段处理。

修复后重跑：40 封全通过，所有阈值和高危项均为零失败。首轮失败明细保留在本地 `.tmp/` 运行历史中，未通过删除样本或放宽断言粉饰。

## 4. 运行方式

```bash
# 仓库默认环境（存在 .env 时）
npm run bench:mail-e2e

# 使用外部模型配置（不把密钥写入仓库）
MAIL_BENCH_ENV_FILE="/path/to/.env" npm run bench:mail-e2e

# 可选：临时切换判断器（默认 flash；可显式跑 jev）
MAIL_BENCH_ENV_FILE="/path/to/.env" MAIL_BENCH_JUDGE=jev npm run bench:mail-e2e
```

产物：

- `.tmp/mail-e2e-benchmark-report.json`
- `.tmp/mail-e2e-benchmark-report.md`
- `.tmp/mail-e2e-benchmark/<timestamp>/ledger.png`
- `.tmp/mail-e2e-benchmark/<timestamp>/reviews.png`

`.tmp/` 产物不提交进 git。
