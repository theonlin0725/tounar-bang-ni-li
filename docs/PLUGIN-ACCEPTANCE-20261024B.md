## 2. 四条静态问题：已修 + 有测试

| # | 问题 | 修法 | 证据 |
|---|---|---|---|
| 1 | `detectJob` 的学习模板分支在 `const add` 之前调用 `add` → 命中模板 ReferenceError | 把模板分支移到 `add` 定义之后 | `npm run test:plugin-acceptance` 里预置模板 → 重载页面 → **无 pageerror 且仍识别到岗位** |
| 2 | `captureNow` 把「入队回执」当成功；popup 显示采集成功 | 新增 `event_result` 消息：flush 后按 `client_event_id` 回查服务端结果，区分 `entered / review / queued / rejected / failed`；popup 文案随之区分 | 验收输出「已自动入账（15ms）」并给出 `application_id` |
| 3 | 插件侧 20000 字截断 + `add` 折叠空白，破坏段落；服务端拒绝无法证明没丢字 | JD 抽取保留换行；超长时置 `jd_text_truncated=true` 并保留前 20000 字；服务端只在**未声明截断**时拒绝 | fixture 落库 `jd_text=119 chars / 8 段`，含「任职要求」 |
| 4 | `learnFromJob` 重新生成选择器后直接标 stable | 已有模板时不再重写；新增 `recordHit()`，只有**换了岗位 ID 仍命中**才升 `stable`，命中失败标 `suspect` | 代码与模板状态字段；真实站点重复命中待下一轮补 |

## 3. 产品行为变化

- **公司补齐**：企业自建招聘域名（`jobs.mihoyo.com` → 米哈游、`job.xiaohongshu.com` → 小红书、`careers.oppo.com` → OPPO、`careers.pddglobalhr.com` → 拼多多、`zhaopin.kuaishou.cn`/`campus.kuaishou.cn` → 快手）现在能补公司；聚合站（BOSS/牛客/实习僧）仍保持 null。
  这样米哈游/小红书这类单雇主站点不再因为缺公司而进待确认。
- **授权即采**：popup 授权后自动对当前页采集（`job_captured`，不伪造停留），状态区分到「是否真的入账」。
- **完整 JD**：端到端 `jd_text`（详情抽屉「JD 全文」），摘要仍 80 字兼容。

## 4. 新增可重复自测命令

```bash
npm run test:plugin-acceptance
```
