## 三、分模块详细技术设计

### M0. 生产域名白名单补全（前置必选，插件升级至 `0.2.12`）

**问题**：线上部署域名 `https://bangnili.theonlin.top` 尚未加入插件与后端白名单（仍硬编码旧域名 `bangnili.app.workbuddy.host`），导致 M1 首次进入的插件检测在线上恒为未安装。

**改造方案**：
1. `extension/manifest.json`：
   - `version` 从 `0.2.11` 升至 `0.2.12`；
   - `content_scripts[0].matches` 增加 `"https://bangnili.theonlin.top/*"`。
2. `extension/background/site-access.js`：
   - 将 bootstrap 域名判断从单域名改为白名单集合（包含 `https://bangnili.theonlin.top` 与 `https://bangnili.app.workbuddy.host`）。
3. `extension/lib/site-access.js`：
   - `appHosts` 数组增加 `'bangnili.theonlin.top'`。
4. `server/src/domain/applications.js`：
   - `isLocalSelfUrl()` 补充读取 `config.appBaseUrl` 的 hostname（如 `bangnili.theonlin.top`），避免自身页面 URL 被误判为外部招聘链接。
5. `tools/build-beta-plugin.mjs`：
   - 打包输出 `bangnili-extension-0.2.12.zip`，确保下载接口同步指向新版本。

### M1. 首次进入渐进式动画引导流（默认落页：投递明细）

**目标路径**：默认路由保持落在「投递明细」（`ledger`），通过顶部/轻量浮层分阶段渐进引导，不阻断用户正常操作，每步支持「暂不提示 / 跳过」，状态持久化避免重复打扰。

**4 阶段状态机设计**：

| 阶段 | 触发条件 | 视觉动画与核心文案 | 主操作与流转条件 |
|---|---|---|---|
| **Step 1：检测插件** | 首次登录进入「投递明细」，自动触发前端插件探测（`probeExtension`，超时 1.2s） | 顶部轻提示条带脉冲检测动效：`正在检测浏览器插件…` | 检测到已安装且已授权 → 直跳 **Step 3**；未检测到或未授权 → 进入 **Step 2** |
| **Step 2：安装插件并授权** | 未检测到插件，或检测到插件但未授权站点访问 | 引导卡片（含极简 3 步图示：下载解压 → 浏览器加载 → 点击授权）<br>副标题：`装好插件，逛招聘页顺手就能记下岗位` | 按钮：`下载插件包 (v0.2.12)` + `已完成，重新检测`；同时后台每 2.5s 自动轮询，一旦授权成功自动流转至 **Step 3** |
| **Step 3：动画指引岗位抓取** | 插件已就绪，且当前账号「插件抓取岗位数 == 0」（`totalJobs === 0`） | 轻量 CSS/SVG 循环演示动画（模拟浏览招聘页 → 右侧浮标 3 秒亮起 → 飞入台账卡片）<br>主引导语：**`直接浏览，3秒入库`**<br>副文案：`去 Boss / 官网打开任意岗位详情页，插件会自动收纳到「看过没投」` | 提供常见招聘站快捷链接与 `我已试过，刷新看看`；当轮询/回页检测到账号**首次成功抓入任意 1 条岗位**后，自动播放完成打勾动效并流转至 **Step 4** |
| **Step 4：动画指引邮件授权与同步** | 已完成首次岗位抓取，且尚未绑定任何邮箱账号（`mailAccounts.length === 0`） | 轻量 CSS/SVG 动画（邮箱信封 → 自动识别笔试/面试/拒信 → 台账状态标签自动翻牌更新）<br>主引导语：**`自动同步更新你的投递状态`** / **`自动入库你的岗位`** | 主按钮：`去授权邮箱`（直达「设置 → 数据与授权」并自动高亮邮箱绑定区）；绑定并完成首次同步后，标记引导全流程完成 |

**实现要点**：
- 新增轻量状态字段存储于用户偏好或 `localStorage`（按 `user_id` 隔离：`onboarding_dismissed_step`），并结合真实后端数据（插件状态、岗位数量、邮箱绑定数量）自动推导当前阶段，杜绝“已完成还弹窗”的问题；
- 动画全部采用纯 CSS + 内联 SVG 实现，无第三方重型依赖，首屏零额外网络请求。

### M2. 简历改写深度优化与表单文案调整（图 2、图 5）

**1. 表单文案微调（图 2）**：
- `web/assets/js/views/resume-rewrite.js`：将额外要求输入框的 placeholder 从 `可选：重点突出数据分析、AI 项目或某个业务成果` 改为 **`改写需求：重点突出数据分析、AI 项目或某个业务成果`**。

**2. 改写 Prompt 与对齐策略强化（图 5）**：
- 修改 `server/src/modules/career-ai/rewrite-workbench.js`：
  - **JD 关键词结构化抽取强化**：在 Step 1 解析 JD 时，强制输出 `core_keywords`（高频业务术语/方法论/工具名）、`target_persona`（岗位核心画像，如“数据驱动的策略运营”）以及 `hard_requirements`。
  - **反“微调偷懒”约束**：在改写指令中明确要求：
    - 对「可优化」的经历与项目描述，不能仅改标点或换一两个同义词，必须**重构句式与业务叙事重心**（如采用「业务痛点/目标 → 动作与方法（自然融入 JD 关键词）→ 量化结果」结构），让招聘方一眼看出与目标岗位画像的匹配度；
    - 严禁编造任何原简历未出现的数字、公司、工具或职责；若 JD 有硬性要求但简历缺少对应证据，归入 `need_user_fact`（待补事实）并给出具体补充提示，绝不硬写进正文；
    - 保持**完整自然句/自然段粒度**，禁止无意义的半句截断或多余换行；
    - 仅当原句本身已经高度贴合 JD 或属于纯客观信息（姓名、日期、学校名称、公司标题）时，才标记为 `unchanged`。
  - **质量自检兜底**：后端对模型返回的 `optimized` 块计算文本编辑距离/相似度；若超过 70% 的业务经历块改写前后字面几乎无实质变化（仅标点或 <5% 字符变动），自动触发一次定向纠偏重试，提示模型增强 JD 关键词融入与表达重构。

### M3. 简历改写左右对照严格对齐与句尾行内标签（图 5、图 6）

**1. 布局重构：由「左右双栏各自流式」改为「逐块同行配对 Grid」**
- `web/assets/js/views/resume-rewrite.js` & `web/assets/app.css`：
  - 废除左右两个独立容器各自纵向堆叠的渲染方式；
  - 改为单一列表容器，每个 block 渲染为一个 `.rewrite-pair-row`（CSS Grid：`grid-template-columns: minmax(0, 1fr) minmax(0, 1fr); gap: 16px; align-items: stretch;`）；
  - 左侧单元格显示原简历对应块（`.rewrite-cell-orig`），右侧单元格显示 AI 改写块（`.rewrite-cell-new`）；
  - 效果：无论某一行是标题、短行还是长项目经历，左右两侧永远**同行顶部严丝合缝对齐**，彻底消除图 6 中的错位问题。

**2. 标签位置与信息密度优化（图 5、图 6）**：
- **`已优化` / `待补事实` 放句尾行内**：
  - 将状态标签改为 `<span class="rewrite-inline-badge is-optimized">已优化</span>`（`display: inline-flex; vertical-align: baseline; margin-left: 6px;`），直接紧跟在改写正文末尾，**绝不放在句子开头，也绝不单独占一行**；
  - `未改动`（`unchanged`）默认**不渲染可见标签**（避免满屏“未改动”撑高行距），仅在鼠标 hover 该行时在右上角极轻展示；
  - 编辑态（点击进入 `contenteditable` 或文本框编辑）时自动隐藏行内标签，失焦保存后恢复显示。
- **改写说明与「还原原句」收口**：
  - 默认仅在右侧卡片底部用单行紧凑灰字（最多 1 行截断，点击或 hover 展开详情）展示「对齐关键词 + 还原原句」按钮，不再把整段 JD 原文默认平铺在每条经历下面，大幅降低视觉噪音并保持左右视觉平衡。

**1. 后端支持**：

### M6. 修复提醒邮件缺失「待回看」岗位（图 4 根因修复）

**已确认根因**：
- 在 `server/src/modules/mail-push/reminders.js` 第 161 行 `buildReminderCandidates()` 中：
  ```js
  if (!(app.status_url || app.job_url)) continue;
  ```
- 大多数通过邮箱自动同步入库的投递记录没有 `status_url` 和 `job_url`。台账列表（`applicationProjection`）判定 `due_for_review` 时**不要求存在外链**，因此页面上显示大量「待回看」岗位；而邮件候选构造器却因缺少外链把它们全部丢弃，导致邮件里只有 C 类（待确认），B 类（该回看了）为空。

**修复方案**：
1. 修改 `server/src/modules/mail-push/reminders.js`：
   - **移除**第 161 行 `if (!(app.status_url || app.job_url)) continue;` 的硬性拦截；
   - 允许无外链的到期岗位正常进入 B 类（`该回看了`）候选集合；
   - 核查 `cardVariables()` 与邮件模板渲染逻辑：
     - 当存在 `status_url` / `job_url` 时，保留「查看官网进度」外链按钮；
     - 当无外链时，优雅隐藏外链按钮，主操作链接指向站内台账详情（`${appBaseUrl}/?app=${app.id}`）以及「确认无变化」一键确认链接（`/r/${token}`），保证每条待回看卡片都可点击处理。
2. 同步补充单元测试与回归用例：
   - 构造「无 `status_url` 且无 `job_url`，但距离上次进展超过回看阈值」的邮件入库岗位，验证 `buildReminderCandidates` 与邮件渲染结果正确包含该条 B 类待回看记录，且与台账 `待回看` 筛选结果口径完全一致。

### M10. AI 助手缺 JD 交互补录卡片

**触发场景**：用户在 AI 助手中提出「分析这个岗位匹配度」「比较 A 和 B 岗位」「帮我按这个岗位改写简历」等依赖 JD 的请求，但目标岗位（或其中一个岗位）的 `jd_text` 为空或有效字数过短（如 `< 30` 字）。

**端到端闭环设计**：
1. **后端编排与工具信号（`server/src/modules/agent/tools.js`、`server/src/modules/agent/orchestrator.js`）**：
   - 当岗位查询/分析工具检测到目标岗位缺少 JD 时，除向模型返回 `missing_jd: true` 标记外，在响应的 `cards`（交互卡片数组）中附加结构化卡片：
     ```json
     {
       "type": "missing_jd",
       "application_id": "app_xxx",
       "company": "ByteDance",
       "job_title": "拉美市场电商产品实习生 - TikTok Shop",
       "current_jd": "",
       "resume_prompt": "用户原始分析指令（如：分析 ByteDance 拉美市场电商产品实习生与我简历的匹配度）"
     }
     ```
   - 若对比两个岗位且两者都缺 JD，支持在卡片中分别列出对应输入框（或按岗位分卡）。
2. **前端内联补录卡片（`web/assets/js/views/assistant.js`）**：
   - 在 AI 回复气泡下方直接渲染「补充岗位 JD」交互卡片：
     - 显示公司名 + 岗位名 + 简短提示（`该岗位暂缺 JD，粘贴后我立刻继续分析`）；
     - 内置多行 `<textarea>` 供用户直接粘贴 JD 文本；
     - 底部操作按钮：**`保存 JD 并继续分析`**（主按钮） + `暂不补充`（次按钮）。
   - **一键续接流程**：
     - 用户点击「保存 JD 并继续分析」后，前端调用岗位更新接口将 `jd_text` 写入台账（同步更新卡片为「JD 已保存 ✓」只读态）；
     - 紧接着自动将 `resume_prompt` 作为续接消息发回当前会话，AI 立即读取刚保存的完整 JD 并输出正式匹配度/对比/改写分析，全程零跳转、无需用户重复打字。
