# 校招采集泛化能力评估（2026-11-19）

本轮以《互联网金融头部公司清单-三方并集_公司并集_表格-网址修正-20261118.csv》的 130 行为基准，复核“招聘网站识别 → 校招详情读取 → 本地判岗 → 大模型整理 → 台账/前端显示”的实际通过率。

测试方式：Playwright + 真实 Chrome 扩展 + 隔离验收服务 + 真实 DeepSeek Flash；不是用假数据或页面标题推测。逐站明细见 `docs/campus-generalization-matrix-20261119.csv`。

**一句话结论：单岗位详情页的泛化链路已经可用，校招入口和校招批次也已经优先处理；但“130 个入口页全部自动出岗位”不成立，也不应该成立——其中大多数是列表页、SPA 壳、登录/反爬页，插件不会把列表页伪装成一个岗位。**

## 1. 能不能识别这 100 多家公司的招聘网站？

能识别“已授权站点”和“具体岗位详情”，但不是“给一个入口网址就自动爬完整站”。

### 已经做到的

1. **公司目录**：`extension/content/adapters.js` 的 `RECRUITMENT_DIRECTORY` 覆盖 123 家雇主，表内 128 个校招入口和 128 个社招入口已同步；BOSS直聘、前程无忧、拉勾、智联招聘、猎聘这 5 个招聘平台不计入雇主目录。
2. **校招优先**：入口与社招分开保存；网页“数据与授权”里先显示“打开校招入口”，再显示“打开社招入口”，不会把社招入口当校招。
3. **共享招聘站按租户识别**：Moka、北森 `zhiye.com`、`hotjob.cn`、飞书招聘、平安共享招聘站都能按租户/路径识别到具体雇主，不会把同一个 ATS 上的其他公司内容算进来。
4. **校招批次识别**：从页面标题和标签识别 `2027校招`、`27届校招`、`2027 校园招聘`、`2026-27 Campus` 等写法；从校招路由打开的详情会带“校招”兜底，模型结果不会把已有校招批次覆盖成全空。
5. **校招详情容器**：对 Moka（微博等）、安永、平安共享站、飞书招聘（广发基金等）、得物这类“详情正文不在 h1/main 里”的模板，增加了受控的详情容器识别，只读取单岗位面板，不把推荐岗位或其他租户内容混进模型输入。

### 还做不到的

- **不能从一个入口页自动翻出所有岗位**。插件当前的产品边界是“用户打开一个具体岗位详情，插件识别并整理”；列表页只产生“发现岗位”事件，不会把整页当成一个岗位，也不会自动翻页。
- **不能代替登录、验证码、安全验证**。遇到登录墙/反爬/短信验证，必须在普通 Chrome 里由用户先完成。
- **不能保证每个入口都自动找到详情链接**。表内或入口页能发现详情链接的只有 30/130（其中入口页自动发现 13 家）；其余需要点击校招导航、等待 SPA 渲染或登录后才能看到岗位。

## 2. 校招岗位能不能优先读取并交给大模型？

可以，但要区分“入口优先”和“详情页识别”：

- 入口层：校招入口排在社招前面（50 家入口与社招不同域/不同路径的公司已标记 `campusFirst`）。
- 路由层：`recruitmentTrack()` 识别 `/campus`、`campus-recruitment`、`reccampportal`、`students`、`campus.grad` 等校招路由。
- 标题层：`batchFromText()` 识别“27届校招”“2027校招”“2026-27 Campus”等，避免校招岗位入库后批次为空。
- 页面层：单岗位详情必须同时满足“唯一标题 + 职责/要求章节 + 非表单/非账号页”；校招详情走同一套本地门槛后才调用模型。

校招详情的实测结果（按标题/批次或校招路由判定为校招的 11 个样本）：

| 结果 | 数量 | 说明 |
| --- | ---: | --- |
| 模型 + 台账 + 前端全部通过 | 8 | 字节、腾讯、美团、拼多多、小红书、得物、微博、Amazon 校招 |
| 模型未通过、规则原文兜底 | 1 | 安永校招项目页 |
| 不是单岗位/自动化超时 | 2 | 广东华兴银行是校招公告；苹果实习页自动化超时 |

在“可用的校招单岗位详情”范围内，8/8 走完真实模型并到前端。

## 3. 这些网址能不能走通全流程？

### 26 个详情样本的逐条结果

| 结果 | 数量 | 公司 |
| --- | ---: | --- |
| 真实模型 + 台账 + 前端 | 20 | 字节跳动、腾讯、阿里巴巴、京东、美团、拼多多、小米、米哈游、小红书、得物、微博、网易游戏（互娱）、Amazon中国、微软中国、OPPO、平安银行、平安证券、中国平安、广发基金、埃森哲 |
| 规则原文兜底到前端 | 2 | 安永、玛氏（模型判断不是单岗位，保留网页识别原文） |
| 正确拒绝：不是单岗位/职位不存在 | 3 | Google（页面明确 Job not found）、广东华兴银行（校招公告，不是单岗位）、天风证券（样本 URL 已变成官网首页） |
| 自动化打开超时 | 1 | 苹果中国（本地普通 Chrome 可尝试，自动化浏览器 15 秒超时） |

有效岗位详情页的前端到达率是 22/22；其中 20 个是完整模型整理，2 个是规则兜底。3 个拒绝项是“防止假岗位/错岗位”的正确行为，不应算作漏采。

### 130 个入口页的结果

| 入口类型 | 数量 | 插件行为 |
| --- | ---: | --- |
| HTTP 200 且有可读正文（≥500 字） | 76 | 可继续点进具体岗位；其中 30 家能发现详情链接（13 家入口页自动发现，22 家为表内样本，二者有重叠） |
| HTTP 200 但正文 <500 字 | 49 | SPA 壳、登录/安全验证、极简首页；需要等待渲染或人工操作 |
| 自动化超时 | 3 | 拼多多、苹果中国、埃森哲（自动化浏览器超时，不等于本地打不开） |
| 没有公开入口 | 2 | 上海量派投资、进化论资产 |

因此，“入口能打开”与“详情能采集”必须分开统计：125/130 入口可访问，但只有 26 个详情样本做了全链路实测；其余 104 家没有可用的单岗位详情样本，矩阵中标记为未测，而不是“通过”。

## 4. 本轮修复（0.2.9）

- 招聘目录结构升级：`entryUrl`（校招优先）+ `socialUrl`（社招）+ `linkedUrls`（详情/最终域名），网页授权卡分开展示“打开校招入口/打开社招入口”。
- 共享 ATS 租户识别：Moka、安永、平安、飞书、得物按租户/路径取雇主，避免跨公司串数据。
- 校招批次：从标题识别 `2027校招`、`27届校招`、`2026-27 Campus`；校招路由兜底；模型不会覆盖更具体的校招批次。
- 详情容器：Moka、安永、平安共享站、飞书招聘、得物单岗位面板；排除表单、推荐岗位和跨租户内容。
- Google `Job not found` 页面直接拒绝；详情页的 `/apply` 路径不再被误拦。
- 列表卡片公司名回退到招聘目录，解决共享 ATS 上公司名为空。
- 回归用例：更新 3 个校招批次快照预期；新增共享 ATS 租户、校招入口优先、授权链接顺序用例。

## 6. 本地部署（可直接自测）

- 网页：<http://127.0.0.1:4310>
- 插件包：`web/downloads/bangnili-extension-0.2.9.zip`
- SHA-256：`64d2372d1daf91aa381a034f8b51b56fdd3259cff7b96378bf4125f388527153`
- 插件默认后台地址已指向 `http://127.0.0.1:4310`，解压后加载 `bangnili-extension` 目录即可。
- 验收数据是真实库的隔离副本；邮件为 `outbox`，不会真发信；模型为 `deepseek-flash`，密钥只在服务进程中，不写入插件包或仓库。

安装顺序：

1. Chrome 扩展管理页打开“开发者模式”。
2. 先停用旧插件，再“加载已解压的扩展程序”，选择解压后的 `bangnili-extension` 目录。
3. 打开 <http://127.0.0.1:4310>，用原有本地验收账号登录，按弹窗确认连接。
4. 进入“数据与授权”，搜索公司并授权；先点“打开校招入口”。
5. 打开具体校招岗位详情，等 2–3 秒，点插件“采集当前页”，到台账详情看 JD 是否显示。

停止服务：`npm run local:stop -- --port 4310`

## 7. 已知边界与下一步

- **列表页不自动变成岗位**：这是有意的安全边界。要在列表页批量采岗位，需要另做“列表采集/翻页”功能，并单独处理同页多岗位、推荐岗位和登录态。
- **SPA/登录/反爬**：百度、华为、vivo、招商银行、京东方、蚂蚁、微众等首屏正文为空或极短，需要等待渲染或用户先登录；自动化浏览器无法替代短信/验证码。
- **外企全球站**：Apple、Google、Amazon 等全球站会按地区/语言跳转，自动化容易超时；本地 Chrome 通常可打开，但需要人工确认岗位地区。
- **共享招聘站的雇主归属**：平安银行、平安证券、中国平安在表内给了三个不同 `positionId`，但页面实际都写着“平安科技”。这是源表归属问题，插件按页面真实雇主入库，不按表名硬改。
- **失效样本**：天风证券的样本 URL 现在打开是官网首页；广东华兴银行的样本是校招公告而不是单岗位；Google 样本已显示 Job not found。这三类不应继续当“岗位详情”使用，建议换新样本。
- **最终域名授权**：入口跳到 `zhiye.com`、`hotjob.cn`、`mokahr.com`、`feishu.cn` 时，要在授权页同时授权最终详情域名，否则只能打开入口、不能采集详情。
