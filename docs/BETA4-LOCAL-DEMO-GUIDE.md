# beta4 本地演示教程（Mac）

核对时间：2026-11-03。针对当前项目源码及本机现有配置。

推荐使用「本机网页 + 本机后端 + 独立数据副本」，无需等待云部署，也不用另外安装数据库或构建前端。AI、真实招聘网页及真实收发邮件仍依赖网络，不是完全离线版。beta4 特有的云快照恢复能力应在云环境验收，本教程不验证它。

## 1. 启动：复制这一段到 Mac 终端

```bash
cd "/Users/mingenlin/Desktop/opencode project/帮你理"
zsh tools/start-beta4-demo.command
```

这台 Mac 已有 Node 26 和项目依赖，不需要重新安装。启动文件也可以在 Finder 中双击；若双击方式找不到 Node，使用上面的终端方式。

保持终端打开。看到包含 `"event":"listening"` 的输出后，在 Chrome 打开：

**http://127.0.0.1:4312**

启动过程：

- 第一次以 SQLite 一致性备份方式，从 `data/mail-selftest/tounar.sqlite` 复制数据和配套密钥到 `data/beta4-local-demo`，包括已提交的 WAL 数据。
- 后续启动复用演示副本，演示过程中添加、修改的记录会保留。
- 使用当前项目代码，读取现有 `.env` 的 AI/Jev/Dify 配置，不覆盖 `.env`。
- 独立监听 4312，不停止当前占用 4311 的服务；关闭云持久化、后台定时任务和真实 SMTP 发信。
- 副本含真实个人业务数据和邮箱连接凭据，仅供本人本机演示；不要分享整个数据目录。手动点击邮箱同步仍可能连接真实邮箱。

当前数据源共有 59 条台账、123 条邮件、62 条待确认记录（包括历史已处理记录）；这是全库数量，不等于登录账号的当前界面数量。旧 `data/tounar.sqlite` 只有 6 条台账，因此这里明确选用较新的数据源。

## 3. 推荐的 5～8 分钟演示顺序

| 顺序 | 操作 | 展示重点 |
|---|---|---|
| 1 | 打开台账，切换已投、看过没投和待确认 | 数据整理与状态总览 |
| 2 | 搜索一个已有公司或岗位，打开详情 | JD、来源、状态历史 |
| 3 | 手动补录一条明确标为「演示」的记录，填写页面必填项 | 从录入到台账出现的完整流程 |
| 4 | 修改该演示记录的状态，再打开详情 | 状态变更和历史留痕 |
| 5 | 展示提醒设置和邮件模板预览 | 通知内容及偏好设置；此环境不会真实发信 |
| 6（联网） | 预先选好一份简历、2～6 个合适岗位，再进入 AI 分析 | 简历与岗位对比；请先试跑一次确认模型可达 |
| 7（联网，可选） | 插件采集一个事先验证可识别的招聘岗位页 | 采集到网页台账的链路 |

现场核心演示以第 1～5 步为主。AI、待确认的智能确认、自动入账都有外部模型依赖，模型失败时应保留真实报错或使用界面提供的手动补录，不应当作离线功能。

## 4. 插件连接本地演示

当前源码插件版本是 **0.2.3**。使用演示专用 Chrome 个人资料，避免切换正在连云端的插件。

1. 在 Chrome 地址栏输入 `chrome://extensions`。
2. 开启右上角「开发者模式」，点击「加载已解压的扩展程序」。
3. 选择 `/Users/mingenlin/Desktop/opencode project/帮你理/extension`，这一层直接包含 `manifest.json`。
4. 打开插件弹窗，手动填写后台地址 `http://127.0.0.1:4312`，点击「保存并授权连接」。默认本机检测只探测 4311/4310，因此这里手动填 4312。
5. 在演示网页的「数据与授权 → 插件绑定」中输入插件配对码并批准。
6. 打开已准备的真实招聘岗位详情页，按插件提示授权该站点，保持页面在前台至少 3 秒，观察采集结果。
7. 回到台账查看结果；识别情况决定记录进入看过没投、已投或待确认，不能保证任何页面都自动入账。

不要为了演示点击真实招聘网站的提交申请按钮。普通浏览可以展示采集；投递状态可在演示副本手动演示。

如果原插件提示有待上传队列，保留原绑定和队列，改用新的 Chrome 个人资料。插件有跨后台隔离规则，不能直接把旧队列搬到新后台。

## 5. 哪些能在本地完成

| 功能 | 本教程中的状态 |
|---|---|
| 登录、已有台账读取、筛选、详情、手动记录与状态修改 | 本机运行，无需云部署 |
| 本地验证码 | 自动填入，不发邮件 |

| AI 简历分析、岗位对比、LLM/Jev/Dify 工作流 | 已检测到本机配置；需要网络，本次未调用真实模型验证 |
| 插件浏览真实招聘网站 | 本地后端可连接；网站访问、权限和适配效果仍需现场前试跑 |
| 历史邮件展示 | 来自本地副本 |
| 新邮件同步 | 需要有效邮箱授权和网络；定时同步在此启动方式下关闭 |
| 真实邮件发送 | 此启动方式关闭；需另用项目邮件自测流程 |
| 云端重部署后恢复数据 | 本地演示不覆盖，留给云部署验收 |

## 6. 结束与下次继续

在运行服务的终端按 **Control+C**。下次重新执行第 1 步即可，演示数据保留。

原 `data/mail-selftest` 和旧 `data/tounar.sqlite` 不会因本教程的页面操作而改变；操作写入独立的 `data/beta4-local-demo`。演示副本不会自动吸收原库后续变化。

如需重新从原库复制：先停止演示，把 `data/beta4-local-demo` 改名备份，再启动。不要直接删除原库或覆盖已有 `.env`。

## 7. 常见问题

- **4312 被占用**：可能已经启动，先打开网页；否则检查占用服务，不要停止开发 agent 的服务。
- **网页打不开**：确认终端出现 listening 输出且没有退出。不要双击 `web/index.html`，它需要后端 API。
- **登录后没有预期数据**：确认地址是 4312，账号是上述 QQ 邮箱；不同用户的数据隔离。
- **验证码或登录反复失败**：确认使用独立浏览器个人资料；频繁获取验证码可能触发限流，稍后再试。
- **AI 或确认入账失败**：本地部署不会消除外部模型依赖。检查网络与服务配置，现场先展示已验证的核心流程。
- **邮件没收到**：此演示明确使用 outbox，不会发送真实邮件。
- **需要真实邮件展示**：现有 `npm run mail:selftest` 是另一套真实 SMTP 自测流程，会使用固定的自测库，不是本教程的独立演示副本。先阅读 `docs/MAIL-SELFTEST-GUIDE.md`，不要在纯展示时混用。
