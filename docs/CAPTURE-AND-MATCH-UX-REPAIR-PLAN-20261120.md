## 一、为什么上次验过，这次仍会错

11 月 19 日的网易专项修复验证了从校招首页定位到 **hr.163.com/job-detail.html?id=67248** 的直链，岗位为“玩法策划（大世界方向-燕云十六声）”。该样本公司、标题、杭州地点、模型 JD 和浏览事件均有记录。它解决了把“工作地点”或“杭州”选作标题的问题。此次四条全部来自 **campus.game.163.com/app/detail/index?id=…&projectId=102**，是另一套页面。验收脚本最终以同岗浏览事件、前端可见和 JD 模型来源判“自动整理成功”，没有逐项比对公司、完整纯标题和城市集合。标题包含正确前缀时也可能过关。[上次验收 §3.5](CAMPUS-AUTO-DETAIL-ACCEPTANCE-20261119.md#35-岗位名纠错网易截图问题) · [旧验收矩阵](campus-auto-detail-matrix-20261119.csv) · [验收判定代码](../tests/e2e/campus-auto-live.mjs)

只读自测库为本机 `20261120-real-resume-selftest`。四条均为 `generic` 适配器，分别有已处理的 `job_viewed`；四条公司和地点的字段来源均为 `unavailable`，JD 均为 `jd_heading_sections`。当前台账公司 **0/4**、地点 **0/4**、纯岗位名 **1/4** 正确。以下官网值可直接作回归预期，公司展示统一使用现有招聘目录名称 **网易游戏（互娱）**。

**公司漏在采集侧。** 用当前适配器对同一 URL 求值：`resolveAdapter` 返回 `generic`，`companyForHost` 无值，但 `directoryEmployer` 已能返回“网易游戏（互娱）”。通用采集只有在结构化岗位、指定语义详情或已验证适配器命中时才把目录雇主加入候选。四个实页都没有 H1，通用语义详情恰好要求唯一 H1。投递按钮等信号足以让记录继续入账，公司证据却没有随同进入这四条记录。仅往目录再加一次公司名无助于修复。[适配器与招聘目录](../extension/content/adapters.js) · [详情判定与字段选取](../extension/content/tracker.js)

**标题错在取值范围。** 四页的 `.position-title` 内都分开存放岗位名和标签。三条错名来源为 `heading_near_apply`，与父节点整体取 `innerText` 再压平空白的结果完全一致。唯一正确的 4731 来源为 `large_visible_text`，碰巧选中单独的名字。模型候选生成同样可能读取整个标题节点，服务端按候选原文验真也无法拆开已粘连的标签。这四条最终保存的是规则字段，现有记录不足以判断当时模型是关闭、失败还是走了其他回退。[本地候选抽取](../extension/content/tracker.js) · [模型候选校验](../server/src/modules/jd-extraction/service.js)

**城市已有原文。** 四个官网详情和已入库的 JD 都有独立的“工作地点”标题，城市在下一行。现有通用文本规则要求标签后有冒号，未覆盖本组布局。台账摘要又从公司介绍开头展示，导致用户很难从列表分辨各岗位。

## 二、开发任务 A｜同时修插件新采集和已有四条记录

1. **统一识别当前岗位。** 为此主机和详情路径补实页模板，用稳定岗位 ID、当前详情区域、职责或要求段共同确认。复用现有招聘目录对这个已确认详情提供公司来源。第三方招聘系统仍按租户或明确雇主判定。不得把整个 163 域名映射成同一雇主，不得凭 JD 中出现客户、产品或合作公司名填公司。
2. **两条路径共用同一份字段证据。** 规则采集与模型 `title_candidates` 先读当前岗位的独立名称元素；在本模板中保留首个名称子节点原文，跳过同级徽标和标签。去掉候选中那个包含名称及标签的父节点。保留括号、斜线、连字符和正式名称内的空格。禁止按第一个空格切词或维护“游戏热爱”等删词表。对结构不确定的页面保留 JD、原链接和补充入口。地点从同一详情的标签及相邻值读取，保留全部城市。摘要优先展示岗位职责相关原句，完整 JD 仍可查看。不要为标签新增必填字段。
3. **逐字段记录来源。** 保留公司、标题、城市、JD 各自来源，区分模型引用、已验证模板、规则回退与缺证。模型开启、关闭、失败时分别验证。模型只能选择有据的值，不能补造字段。浏览只能进入“看过没投”。
4. **原地修复存量。** 在隔离副本预演，按账号、原始站点/租户、岗位 ID、原始规范链接唯一匹配。注意旧记录的站点键是 `generic`，新适配器若换键，必须演练跨键重访。现有自动改名只接受同岗且高可信模型标题，新模板的证据要有等价而受限的纠正规则。逐字段保护人工修改，补空公司、城市，纠正三条机器错名；4731 的标题应原样保留。冲突进入人工确认。保留原记录 ID、状态、历史、邮件关联和旧报告快照。输出修复预览、来源与前后值，可重跑，实际用户库另行执行。[现有同岗纠错](../server/src/domain/applications.js) · [历史字段修复原则](HISTORICAL-FIELD-REPAIR-20261101.md)

## 三、开发任务 B｜先读结论，按需展开证据

当前 `matchCoreCard` 同时输出结论、摘要、依据；`renderMatchReport` 先画门槛表，`renderDimensionCard` 又画门槛汇总及各维度全套字段。摘要“查看依据”目前只滚动到卡片。改动集中在[单岗位报告视图](../web/assets/js/views/career.js)。下面是本次对旧展示要求的更新，证据核验和纠错能力继续保留。

| 页面位置 | 默认展示 | 点击后的行为 |
|---|---|---|
| 顶部两张卡 | “能力匹配度 · 结论”和“投递优先级 · 结论”，各一项。去掉两卡内摘要、引文、依据和模型处理说明 | 无须点击即可读完两个结论 |
| 卡片下方 | 总体建议保留一句可执行建议。有已核验的硬冲突时保留阻断提示；多项可显示首项和总数 | “查看门槛”展开并定位六维中的硬性门槛 |
| 六维匹配分析 | 突出区标题。硬性门槛、技能工具、经历项目、行业业务、偏好地点、成果量化各一张紧凑摘要卡，只显名称、结论徽标和展开箭头。无独立门槛检查区 | 建议桌面两列、手机一列。整行支持点击；一次展开一项，再点可收起。详情承接在所在行下方，占可用全宽 |
| 优势与缺口、下一步行动 | 保留总结、五项行动及已确认补充入口 | “查看依据”先展开目标维度，定位相关引文。纠错预览、确认和重新分析沿用当前流程 |

**展开后的统一排版**

- 硬性门槛直接复用同一份 `hard_gates`。桌面用对照表，每行一项，列为“岗位要求｜你的对应信息｜结果｜判断依据”。依据先给一句短理由，可点开 JD、简历或用户确认补充的原文。手机将每一行转为带标签的小块。无门槛时展示“JD 未列明硬性门槛”。去掉原先分号拼成的总段和重复的清单。
- 其余五维用“岗位要求｜你的证据｜判断”三列。每行只讲一个要求。下面按需给出“已具备”“待补证/明确缺口”和一条具体行动；长引文放进“查看原文”，关联对应要求。已有报告如果只有维度级证据，就按维度展示来源，不能擅自把引文配到某条要求。保留“补充或纠错”。
- 例如图形岗技能展开后，可见“C++ 项目实践｜现有材料未说明｜待补证”，下一步为“补充一个你使用 C++ 的项目和负责的环节”。Python 或 SQL 的真实经历可在原文中查看；缺少与本项要求的关联时，不应列成 C++ 优势。文案以一个短句说明要点，全文始终可打开。
- 复用页面已有色板：深绿配“匹配/满足”，琥珀配“部分匹配/需要用户确认”，灰配“无法判断/信息不足”，红配“明确不匹配/不满足”。用文字和图标共同表达状态。门槛四态与维度四态分别显示。对照表已足以支持决策，现阶段没有评审通过的权重或分数，不绘制百分比或雷达图。
- 使用原生按钮或 disclosure 语义。Enter、空格可切换，屏幕阅读器可获得展开状态；折叠内容退出 Tab 顺序。在同一报告打开原文或取消纠错后恢复原卡和焦点；切到另一份报告默认全部收起。所有展开、定位、收起操作均为本地展示，模型调用和业务写入均为零。

### 截图还暴露了一项判断问题，建议独立提交

岗位 4739 的现存 `match-v2` 报告把“计算机视觉或图形学等相关研究方向”判为“不满足”，依据仅说明所列专业和“未呈现”该方向。未列在简历上的研究经历，不能证明用户没有。其余四项（含 C++ 和渲染技术）也进入同一门槛列表。当前通用门槛分支可在引文存在时沿用模型的否定结果，真实性核验没有充分验证这段话能否支持该结论。[门槛发现与判断](../server/src/modules/career-ai/llm.js)

单独修判定逻辑：先区分不可妥协条件、岗位技能与加分项，再检查用户证据是否直接支持满足或直接冲突。只有“未提及”、专业名称不同、经验描述不详时标为“信息不足”或“需要用户确认”；当前例子不能据此触发红色阻断。有明确且可核验的冲突时仍强制“暂缓”。顶部、门槛卡、总体建议共同读取同一核验结果。只对新分析生效，旧报告原样可回看，用户重跑产生关联的新版本。这一项和折叠界面分别验收。

## 四、自测脚本与放行条件

在独立账号或隔离库安装**实际待发的插件包**，记录包版本、项目提交、测试时间与模型开关。优先从官网列表点击上述四岗，正常停留后从“看过没投”核对，再打开原岗位、匹配选择器和新生成的报告核对显示名。每例保存预期值、实测值、字段来源、同岗事件及前端截屏。页面下线记为实站未验证，留存脱敏 DOM 固定样本继续回归。

| 用例 | 操作 | 通过标准 |
|---|---|---|
| A1 四个新岗位 | 依次点击四岗，分别跑模型启用、关闭及模拟失败；隔离各轮数据 | 每种模式四条公司、纯标题、城市逐字段完全正确；JD 包含当前岗职责和要求，摘要能区分岗位。每轮仅四个岗位，浏览不算已投递 |
| A2 重访与切换 | 直链进入、刷新、返回列表、快速从 A 切 B；复测此前通过的 67248 | 同岗无重复记录；迟到响应不串岗；三个括号正式名保持完整。旧模板原字段不回退 |
| A3 负例 | 纯列表、相关推荐、多租户招聘站、无明确雇主、公司介绍提及其他企业 | 纯列表停留不产生单岗浏览事件；只采当前岗位；证据不足可补录，绝不把平台或客户当雇主 |
| A4 旧数据 | 在四条旧记录副本预演再执行两次；另备已人工改名、已进入测评、同数字 ID 不同站点样本 | 四条原 ID 保留，三条标题修正，一条保持；四条公司城市补齐。二次执行零新增、零重复改写。人工字段、投递状态和关联历史均保留 |
| B1 首屏与展开 | 桌面 1440px、平板 768px、手机 390px 打开报告；逐张切换、收起，检查触屏与键盘 | 顶部两卡只有结论；总体建议与适用的门槛提示保留；六张默认收起，无独立门槛表。展开仅显示所选项；移动端无横向溢出 |
| B2 依据与纠错 | 从门槛提示、优势和缺口各点一次“查看依据”；补充 Tableau 经历，先取消，再预览、确认、重跑 | 展开到正确维度/来源，确认前画像无变化，确认后按所选作用域生效；新报告可用该证据，原报告可回看。折叠不触发重新分析 |
| B3 状态与兼容 | 分别输入明确冲突、仅未提研究方向、门槛全部满足、无门槛、加分项、缺证据的旧报告、失败报告 | 仅能证明冲突的条件触发硬阻断；专业不同不能单独触发。四态可区分；历史报告保持原结论和恢复入口，失败报告可重试 |
| B4 原功能回归 | 走台账与侧栏、单岗/多岗对比、五项行动、旧深链；在隔离数据中检查手动改状态、邮件同步及邮件人工确认 | 展开与纠错不改变投递状态、日期或提醒；三个已有状态更新来源仍正常，无新增 Agent 对话入口 |
