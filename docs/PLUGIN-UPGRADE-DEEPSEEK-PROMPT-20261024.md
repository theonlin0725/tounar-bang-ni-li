## 开发 Prompt 开始

你现在负责「帮你理」浏览器插件的增量开发。请先阅读当前仓库代码、数据契约与测试，再实现以下需求，完成插件、后端和前端的联调与验证。不要只提交方案、选择器列表或静态演示。

### 一、目标与术语

本次升级包括三个必须打通的能力：

1. 跨招聘网站采集：首先覆盖下列 10 个指定站点，在可正常访问的同类岗位页面上，达到与腾讯招聘相近的识别速度和数据质量。
2. 授权后立即工作：用户打开招聘网页，点击「将本站设为招聘网站并授权」，无需手动刷新，插件立即识别当前页、采集岗位信息，并同步到「帮你理」前端。
3. 记忆和学习：记住已授权站点及页面模板，首次识别成功后保存可复用规则；后续访问优先使用本地规则，页面改版时检测失效并重新学习。未知站点也必须具备这条通路。

这里的「批词」按「招聘批次」实现，例如 2027 届秋招、春招、日常实习；毕业届别、招聘类型和招聘批次不能随意混为一谈。JD 指职位描述、岗位职责和任职要求，不指用户个人简历。

「学习」优先指识别页面结构并生成、验证、保存提取规则，不要求训练或微调大模型。「更新状态」需要分别记录站点规则健康状态和岗位内容变化，不能与用户的投递进度混用。

### 四、功能一：通用页面识别和岗位提取

#### 4.1 先识别页面类型

至少区分：招聘首页、岗位列表、岗位详情、内嵌详情面板、申请表单、申请状态页、登录/验证/错误页，以及非招聘页面。

用户将站点标记为招聘网站，是允许尝试识别的强提示，不能据此断定该站点所有页面都有岗位。

采用可解释的多信号判断：实际岗位内容、语义标签、结构化数据、重复岗位卡片、职责与要求区块、岗位链接和按钮，以及已验证模板。URL 关键词只能作为其中一个信号。缺少投递按钮不应自动否定内容明确的岗位详情。

#### 4.2 提取与降级路径

推荐采用以下路径，并为字段冲突制定明确规则：

1. 校验通过的站点适配规则或已学习模板，作为快速路径。
2. 页面中的 `JobPosting` 等结构化数据，并核对其与当前显示岗位一致。
3. 通用 DOM 语义提取：标题、公司、岗位元信息、职责、要求、重复卡片结构。
4. 低把握时进入受控的大模型辅助识别，或让用户点选字段区域进行一次性教学。

即使命中规则，也需要检查岗位身份、节点有效性和字段质量。规则存在不等于仍然有效。

- 详情页采集当前岗位完整内容；列表页采集当前已加载的岗位卡片和可见字段。
- 只出现在详情页的 JD 标记为待补充，不能把列表摘要伪装为完整 JD，也不能把多个岗位正文拼接。
- 用户打开详情页或侧栏后，增量补齐同一岗位。
- 招聘首页若没有岗位，提示「已授权，请打开职位列表或详情页」；若存在岗位卡片，可按卡片采集。
- 聚合平台的公司名必须来自该岗位的雇主信息，不填「BOSS 直聘」「实习僧」，也不把公司总部当岗位城市。
- 原文未提供的批次、薪资、城市或日期保留空值并说明缺失原因，不能根据当前年份或模型常识补写。

#### 4.3 字段与来源

兼容现有字段命名，至少支持：

| 字段 | 要求 |
|---|---|
| 公司、岗位名称 | 从当前岗位证据提取，不混入站点标题、导航或推荐岗位 |
| 站点和岗位 ID、岗位 URL | 保留 query/hash 中真正标识岗位的内容，去掉追踪参数和凭据 |
| 工作地点 | 支持多城市，与公司地址区分 |
| 招聘批次、招聘类型 | 分别记录，原文不明确则不推断 |
| JD 完整文本 | 保留职责、任职要求、加分项和段落边界；优先存纯文本 |
| JD 摘要 | 兼容现有 `jd_summary`；完整内容另增 `jd_text` 或等价字段，不沿用 80 字截断 |
| 可选信息 | 页面明确给出时提取薪资、学历、经验、部门、发布时间、截止时间 |
| 采集元信息 | 来源页面、采集时间、页面类型、提取方式、规则版本、字段置信度和最小证据 |

新增完整 JD 字段时，打通插件 → 队列 → API 校验 → 数据库存储 → 查询接口 → 前端详情展示。明确字段长度上限；若确需截断，返回截断标记，不能静默丢失正文。

### 五、功能二：授权当前标签页后立即识别和同步

完整链路应为：

用户点击授权 → 浏览器确认权限 → 核对目标标签页与站点 → 注册后续页面脚本 → 对当前已打开页面立即注入或唤醒已有脚本 → 返回脚本就绪确认 → 识别当前内容 → 提取并展示采集状态 → 上传 → 后端确认 → 前端自动刷新对应数据。

具体要求：

1. 无需用户刷新页面，也不能只显示「授权成功」就结束。
2. 已有脚本时发送重新识别指令，避免重复安装 observer、计时器和事件监听。
3. 操作期间切换标签页、页面跳转或 popup 关闭，应保持任务关联正确；异步任务由适当的持久任务机制接管，不依赖 popup 一直打开。
4. 支持 SPA 路由、hash、异步加载、局部详情侧栏和用户滚动后出现的新岗位。不要假定隔离环境中重写 `history.pushState` 就能观察到网站全部路由变化，应实测。
5. DOM 监听采用增量处理、防抖和最大等待时间；无关动画或广告反复变化不应让识别无限等待。
6. iframe 或跳转到新域名时，检查实际权限并明确反馈。不能默认父页面授权覆盖跨域内容。
7. 区分「未授权、准备中、等待页面加载、识别中、已识别、待上传、已同步、字段待补充、需要登录/验证、识别失败」。只有后端确认成功后才能显示已同步。
8. 网络失败进入现有可靠队列，有限退避重试；重复点击、浏览器重启和重试不会重复创建岗位。
9. 撤销某站点授权后，停止当前脚本采集、监听和新任务，并处理尚未发送的该站点数据；下次访问也不得继续运行。保留或删除已同步业务记录按独立设置处理。

快速采集与现有业务事件分开：

- 用户显式发起采集后，可立即创建「采集线索」或等价候选记录；必要时增加兼容的新事件/API，不能借用 `application_submitted`。
- `job_viewed` 仍遵守真实停留条件；列表出现某个岗位不等于用户看过其详情。
- 采集候选不计为已投递。只有真实提交成功证据才能推进投递状态。

### 六、功能三：授权站点记忆、模板学习和更新

#### 6.1 站点档案

持久保存授权站点档案，最低包含：实际授权 origin、用户站点标记、启停状态、授权时间、最近访问、最近识别成功时间、最近错误及失败次数。

权限是否有效以浏览器实时权限为准，档案不能覆盖权限检查。当前站点权限不能通过模糊后缀匹配扩张到其他子域名或近似域名。

同一域名可有多个页面模板。模板按 origin、路由形态、页面类型和结构特征识别，存储：

- 模板 ID 与版本；适用路径及适用范围。
- 岗位卡片或详情根容器、字段定位规则、语义锚点和备用规则。
- 结构指纹、成功样本数、最近验证时间、健康状态。
- 规则来源：内置适配、通用识别、用户教学或模型辅助。
- 上一稳定版本，以便失败回退。

规则保存在扩展本地并能跨重启复用；若提供服务端同步，应按用户隔离，不同步招聘站点会话或凭据。

#### 6.2 学习闭环

首次访问未知模板 → 通用识别 → 字段校验 → 必要时 AI/用户点选辅助 → 生成候选规则 → 当前页面回放验证 → 持久保存 → 在同模板其他岗位上再次验证 → 提升为稳定模板。

至少做到：

1. 规则记住「如何定位字段」，不能缓存第一份 JD 后套给其他岗位。
2. 单页成功只标记试用；跨岗位验证后再标记稳定。列表和详情分别验证。
3. 优先稳定属性、语义锚点和相对容器，避免只有绝对节点序号或容易变的 CSS 类名。
4. 再次访问相同模板时优先走本地规则，正常情况不重复调用大模型。
5. 检测关键字段消失、匹配到多个无关块、岗位身份冲突、质量显著下降等失效信号；广告或岗位文本变化本身不应导致频繁重学。
6. 模板失效后降级到通用识别，必要时重新学习；新规则验证失败时保留旧规则和已有数据，不覆盖成空值或错误值。
7. 用户可以查看已记忆站点、重新识别、重新学习、停用、撤销授权和删除学习记录。用户修改单个字段值，不自动等于确认了全站提取模板。

#### 6.3 更新状态

把以下三类状态分开建模与展示：

- 规则状态：未学习、试用中、可用、疑似改版、需重新学习。
- 岗位内容状态：首次发现、已更新、内容未变、明确下线；通过规范化内容摘要比较实质变化。
- 用户申请状态：沿用原有投递进度机制，不由布局变化或采集失败推断。

默认在用户再次访问站点或主动重新扫描时检查更新。定时巡检全站另属后续范围，不应隐式引入。登录失效、空列表、网络错误或暂时未看到岗位，都不能作为岗位已下线的确证。

### 七、大模型的使用方式

大模型是未知模板识别和失效修复的可选增强能力；已验证模板的采集速度不能依赖每次请求模型。

如接入大模型：

1. 经后端统一调用，支持模型、超时和额度配置；API Key 不写入插件或前端。
2. 只发送必要、脱敏的岗位候选区块和结构信息；保留足够节点标识以便校验定位。排除个人简历、表单内容、聊天、联系方式、Cookie 和令牌。
3. 网页文字是待提取数据，不能作为模型的新指令。模型只返回受约束的 JSON：页面类型、字段候选、证据节点、置信度及声明式规则。
4. 不执行模型生成的任意 JavaScript、脚本字符串或远程代码。声明式规则限制操作种类、规模和执行成本，并在本地验证。
5. 验证字段确实来自页面、规则可以定位、结果属于同一个岗位；模型输出空、超时、格式错误和内容冲突均有降级路径。
6. 相同学习任务去重、缓存并设置重试上限和冷却时间，避免每次 DOM 变化触发模型。
7. 未配置模型时，已有站点、通用规则和用户教学仍可用；如模型端到端联调未完成，应如实列为未完成，不能以 mock 结果冒充。

### 八、性能目标与测量方式

以下是本需求建议采用的验收目标，不是已测结果。实施前先测腾讯基线；如存在不可兼容的技术限制，说明原因和替代方案，不得悄悄放宽标准。

分别记录：

- 交互反馈：用户点击授权或采集，到出现明确状态提示。
- 页面等待：内容尚未出现到本次目标岗位内容已可读取。
- 本地识别：已有权限且本次目标内容可读取，到生成通过校验的结构化结果。
- 上传同步：本地结果生成，到后端确认及前端可见。
- 首次学习：触发学习，到规则验证和保存完成。

建议门槛：

| 项目 | 验收目标 |
|---|---|
| 交互反馈 | 300ms 内出现明确反馈；不包含等待用户点击浏览器权限弹窗的时间 |
| 规则命中后的本地识别 | P95 ≤ 1 秒 |
| 与腾讯比较 | 各站点同类场景 P50/P95 分别 ≤ 腾讯对应值 × 1.2 + 200ms；同时满足本地识别绝对目标 |
| 前端可见 | 正常服务和固定测试网络下，本地结果生成后 P95 ≤ 2 秒；无须手动刷新 |
| 首次未知模板学习 | 立即反馈正在学习；设置可配置超时，建议默认 15 秒，超时后提示并提供降级路径，不承诺所有站点 15 秒成功 |
| 可靠性 | 测试中不串岗位、不重复入账、不覆盖人工修正，不用错误值换速度 |

同一设备、浏览器版本、网络、后端和测试口径下比较；固定旧版腾讯基线，并同时报告升级后腾讯结果，不能靠放慢腾讯满足对比。

列表按相近卡片数量比较，详情按相近内容规模比较；分别报告冷启动、规则命中、首次学习，不混成一个平均值。建议每个被比较场景采样不少于 30 次并保留原始耗时。页面加载时间单列，同时报告用户感知总耗时；不能通过事后选取起点隐藏延迟。

### 九、验收要求

#### 9.1 指定站点

每个必选站点至少覆盖 1 个当前真实列表和 3 个不同岗位详情；如包含不同模板，逐模板补样本。样本中有公开入口时优先使用公开页，需要登录时使用用户正常浏览得到的可访问页面。

对每站人工核对公司、岗位名称、城市、批次、JD、ID 和 URL。分别报告正确、错误、页面存在但漏采、原页不存在四类结果：

- 精确率 = 正确提取字段数 / 所有非空提取字段数。
- 召回率 = 正确提取字段数 / 原页实际存在的目标字段数。
- 核心字段总体精确率目标 ≥ 98%、召回率目标 ≥ 95%；同时列出逐站结果，少样本不能只给百分比。
- 原页没有的批次或其他字段不进入应采分母；原页存在但留空属于漏采。
- JD 需核对职责和任职要求是否完整、是否混入其他岗位内容、是否被截断；不能只检查字符串非空。
- 首次授权当前页后无需刷新，完成从采集到前端可见的真实演示。

BOSS 等页面如出现登录或验证障碍，记录真实失败状态和环境。不能把验证页当成功样本，也不能自行移出必选清单；在获得正常页面前，该站点保持未完成验收。

#### 9.2 未知站点与学习复用

在种子清单外再选至少 3 个不同布局的真实招聘站点，避免仅挑同一招聘系统模板：

1. 事先无专用域名规则，授权后能进入通用识别/学习。
2. 在岗位 A 生成规则，在未用于学习的岗位 B 上验证复用，且不复制 A 的字段值。
3. 重启浏览器或扩展后，规则仍可使用。
4. 模拟关键结构变化，能发现失效、降级和重新学习。模拟结果与线上实测分开标记。
5. 关闭模型后，已保存规则仍可正常工作。

#### 9.3 回归与异常

至少验证：重复授权、拒绝授权、撤销授权、popup 关闭、标签页切换、SPA 快速换岗位、同名不同 ID 岗位、hash 路由、局部侧栏、无批次、字体乱码、需要登录、服务不可用、断网恢复、队列重试、模型超时和非法输出。

特别验证「浏览/采集」不会变成「已投递」，用户人工修正不会被新抓取覆盖，多个用户的数据和学习规则不会串用。

运行仓库现有相关测试，并为新增链路补充有意义的自动化测试。真实浏览器验收、离线 DOM 回放和模拟测试分别报告；离线快照不能证明真实站点速度或当前授权流程正常。

### 十、实施顺序与交付

按以下顺序推进，三个阶段都属于本次升级，不得把第三个功能仅写进未来计划：

1. 打通授权当前页、立即识别、完整 JD、上传与前端展示；先建立腾讯性能与字段基线。
2. 完成 10 个指定站点的当前页面适配，统一通用提取与动态页面机制，完成逐站验收。
3. 完成站点档案、模板学习、持久复用、失效检测和重新学习，并验证未知站点；按配置接入模型增强。

最终交付：

- 具体根因、修改文件和关键实现说明。
- 可运行代码、必要的 schema/API 兼容迁移、配置项及启动说明。
- 逐站支持矩阵：域名、列表/详情模板、登录要求、已验 URL、时间、成功与失败原因。
- 性能报告：改造前腾讯基线、改造后腾讯与其他站点 P50/P95、样本数和原始测量数据。
- 字段质量报告：正确/错误/漏采/原页缺失，完整 JD 检查结果。
- 学习闭环证据：首次学习、另一岗位复用、重启复用、改版恢复。
- 测试结果、未完成项和已知限制，不将受阻或未测场景写成通过。

以「授权后能在前端看到正确岗位；再次访问能快速复用；未知站点能学习」作为完成标准。直接落实代码并验证，不停留在建议或接口占位。
