## D01 ｜「看过」到底怎么算 —— 3 秒门槛

**场景 A**：你在 BOSS 上划过一个岗位，2 秒就划走了 → 不记录。
**场景 B**：你点开认真看了 3 秒以上 → 记一条「看过没投」。
**场景 C**：你开着 10 个标签页，这个岗位在后台 → **不累计**（切走了就停表）。
**场景 D**：SPA 站点（不刷新页面换岗位）→ 换岗后重新计时。

| 选项 | 含义 |
|---|---|
| A（现状） | 当前标签页可见 + 同一岗位累计 ≥3 秒；切后台暂停；换岗重计 |
| B | 放宽到 ≥2 秒（召回更多，噪声更多） |
| C | 收紧到 ≥5 秒（更干净，易漏） |

- 选错的代价：放宽 → "看过没投"列表暴涨，像垃圾箱；收紧 → 你明明看过却没记，会觉得插件失灵。
- 建议：**A（维持现状）**。

**已按你的意见处理**：你说「3 秒门槛可以」→ **冻结为 A**，不再改。

## D02 ｜哪些站点算"支持"，聊天算不算投递

**场景**：你在 BOSS 上跟 HR 打招呼、聊了两句 —— 这算"投了"吗？现在**不算**，也不采集聊天内容。

| 选项 | 含义 |
|---|---|
| A（现状） | 只采集「已授权站点的 Web 岗位详情页 + 有确证的成功提交」；聊天页不采、打招呼≠投递 |
| B | 把"HR 已读/已回复"也算弱证据进待确认 |
| C | 明确列出 ≥8 家站点白名单，名单外一律不采 |

- 建议：**A + C**，先把站点名单定下来（这是 D02 真正缺的东西）。
- **需要你提供**：优先支持哪 8 家（腾讯/字节/阿里/美团/京东/小米/百度/网易/牛客/实习僧/BOSS 里挑）。

## D03 ｜"看过没投"的线索多久自动归档

**场景**：9 月看了 40 个岗位没投，10 月它们还在主列表里，越堆越乱。

| 选项 | 含义 |
|---|---|
| A（现状） | 永不自动归档（`BROWSE_ARCHIVE_DAYS=0`），只能手动归档 |
| B | 30 天未投自动归档，仍保留、可查，不计入累计投递 |
| C | 60 天自动归档 |

- 选错的代价：A → 列表越来越长；B/C → 你可能还想看的老线索被折叠。
- 建议：**B（30 天）**。归档只是折叠，不删除，随时能翻出来。

## D04 ｜什么算"同一个投递"（去重边界）

**场景 A**：同一家公司同一个岗位，你投了两次（春招 + 秋招）→ 应该是 1 条还是 2 条？
**场景 B**：公司名一样、岗位名一样，但城市不同 → 合并还是分开？

| 选项 | 含义 |
|---|---|
| A（现状） | 只有稳定 ID / 规范化链接完全一致才合并；仅"公司+岗位"相同只作待确认候选，不自动合并 |
| B | 公司+岗位+城市相同即合并 |
| C | 公司+岗位相同即合并（最激进） |

- 建议：**A**。宁可让你手动合并，也不要系统偷偷吞掉一次投递。

## D05 ｜终态能不能改（已 offer / 已挂 / 已结束）

**场景**：系统把一条误判成"已拒绝"，其实是"面试中"。现在**改不回来**，只能看到 `D05_NOT_FROZEN`。

| 选项 | 含义 |
|---|---|
| A（现状） | 终态锁死，一律不能改 |
| B | 允许人工纠错，但**强制填原因 + 全程留痕**（审计可查） |
| C | 终态可自由改 |

- 建议：**B**。锁死是数据洁癖，但"改错了没法救"会直接毁掉信任。

## D06 ｜提醒频率与阈值

**场景**：你现在每周一 08:00 收到一封汇总邮件；B 类（超过 14 天没动静的岗位）同一条 7 天内最多提醒 1 次。

| 选项 | 含义 |
|---|---|
| A（现状） | A 类每日 08:00；B 类默认每周一；阈值 14 天；同记录 7 天频控 |
| B | 全部每日 |
| C | 全部每周一 |

- 冲突点：设置里改成"每日"后，7 天频控还生效吗？需要一句话定死。
- 建议：**A，并把"每日"明确解释为"B 类候选每天重算，但同一条记录 7 天内最多出现 1 次"**。

## D07 ｜「已面 N 天」怎么算

**场景**：你进了一面，一周过去了。系统要不要自动算"已面 7 天"？

| 选项 | 含义 |
|---|---|
| A（现状 + 你的意见） | **不推断面试完成**；只在提醒邮件里打「已面 N 天」标签，锚点取面试时间→面试完成时间→进入面试状态的时间 |
| B | 面试后自动推定完成并计算天数 |
| C | 不做这个标签，只显示"已投 N 天" |

**已按你的意见处理**：你说「已面 N 天是作为邮件提醒的标签」→ **冻结为 A**，邮件里已加上该标签（面试中显示绿色「已面 N 天」，其余显示灰色「已投 N 天」）。

## D08 ｜自动判定要不要上"分数阈值"

**场景**：邮件里出现"很遗憾"→ 系统能不能直接判"已挂"？现在**终态一律进待确认，不自动判**。

| 选项 | 含义 |
|---|---|
| A（现状） | 终态必须人工确认；不使用 LLM 自评分自动上线 |
| B | 引入规则分数，>0.9 自动判，<0.9 进待确认 |
| C | 全自动判定 |

- 建议：**A**。误判"你挂了"是最伤人的错误。

## D12 ｜必填字段与"真实缺失"（本次重点）

**场景 A（自动路径）**：插件在你点击"投递成功"那一刻自动抓到公司/岗位/JD 摘要/链接/时间 → **直接入账，你什么都不用做**。
**场景 B（兜底路径）**：插件没抓到（站点太乱）→ 你去"归档线索（补录）"，此时**先选一条插件已采集的线索一键自动填充**，你通常只需补投递时间。
**场景 C（真·兜底）**：插件完全没采到 → 才需要你手填。缺 JD/链接/投递时间会被拒绝（422），且**不用今天代替**。

| 选项 | 含义 |
|---|---|
| **A（你的意见，已落地）** | 自动采集为默认路径；手动补录只是兜底；补录表单支持从插件线索自动填充 |
| B | 允许"标记缺失"后进待确认，后续再补 |
| C | 完全放开必填 |

- 建议：**A 为主 + B 作为开关**。当插件采不到 JD 时，允许标"摘要待补充"进待确认，而不是直接把线索丢掉。

**已按你的意见处理**：补录弹窗新增「从插件采集到的线索自动填充」下拉；插件 JD 摘要新增 meta/正文兜底链，提高自动命中率。
