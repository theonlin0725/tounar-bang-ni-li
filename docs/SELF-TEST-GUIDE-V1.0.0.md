# 帮你理 Tounar v1.1.1 产品自测指引

**版本**：v1.1.1（AI 助手 + 简历改写工作台）
**插件版本**：0.2.11  
**适用对象**：产品、设计、运营与内测同学

本指引按 6 个模块自测（模块 e 为 AI 助手，模块 f 为简历改写工作台）。每项都给出操作路径和验收标准；请如实记录结果，不要用模拟数据替代真实页面/真实邮箱验收。

> **范围声明**：v1.1.1 已包含 AI 求职助手、求职画像和简历改写工作台；请额外验收模块 (e)(f)，原简历版本不得被覆盖。

---

## 0. 启动前准备

### 0.1 环境

- Node.js **≥ 24**
- Chrome / Chromium（用于加载 0.2.11 插件）
- 可选：一个测试 QQ / Foxmail 邮箱及客户端授权码；163 / 126 / yeah.net 代码已支持但尚无真实公网联调证据

### 0.2 启动空库

```bash
npm install
cp .env.example .env
# 编辑 .env，设置 ALLOWED_EMAILS=你的测试邮箱
npm start
```

打开 <http://127.0.0.1:4310>，用 `ALLOWED_EMAILS` 中的邮箱登录。开发模式验证码在 outbox：

```bash
npm run otp:latest
```

### 0.3 启动真实数据隔离副本（需要真实库时）

```bash
npm run local:acceptance
# 默认 http://127.0.0.1:4311
```

该命令只读取原库并复制副本到 `~/tounar-acceptance/<时间戳>/`，不会直接修改原库。

## 1. 模块 (a)：岗位 JD 抓取（官网泛化性）

### 步骤

1. 在仓库运行 `npm run build:plugin`。插件 ZIP 是构建产物，`web/downloads/` 默认不提交；构建后使用 `web/downloads/bangnili-extension-0.2.11.zip`。
2. 解压 ZIP；Chrome → `chrome://extensions` → 打开「开发者模式」→「加载已解压的扩展程序」→ 选择**直接包含 `manifest.json` 的 `bangnili-extension` 目录**。
3. 登录帮你理，进入「设置 → 数据与授权」，使用「检测并连接插件」或 8 位手动配对码完成绑定。
4. 至少打开 **3 家不同招聘官网**的岗位详情页，每个页面停留 ≥3 秒。
5. 回到「看过没投」和详情抽屉检查采集结果。

### 验收标准

- [ ] 插件显示已连接，设备在设置页可见。
- [ ] 打开/刷新/切换帮你理自身页面（127.0.0.1 / localhost）不会新增采集记录。
- [ ] 至少 3 家站点都能进入「看过没投」，公司名、岗位名、JD 摘要/全文有合理结果。
- [ ] 详情抽屉可查看岗位链接、完整 JD，字段无明显串行（例如公司名不是站点名/域名）。
- [ ] 低置信度标题重新打开原文时可以纠正，但不会覆盖人工编辑。

### 对应自动化

```bash
npm run test:netease-game   # 站点快照与 JD 字段（60 项）
npm run test:self-page      # 自身页面排除（6 项）
npm run test:panel          # 同页单岗面板（8 项）
```

## 2. 模块 (b)：前端页面改造点

### 2.1 桌面端

1. 打开 <http://127.0.0.1:4310>，确认左侧导航固定显示：
   - 工作台：投递台账 / 看过没投 / 已归档
   - 待确认
   - 分析：匹配分析 / 简历库
   - 设置
2. 检查投递台账：
   - 顶部是否有旧四标签栏？（不应有）
   - 表头是否只有 5 列：公司、岗位、状态、已投天数、更新时间？
   - 状态是否是圆角颜色块下拉？切换状态后颜色立即变化。
   - 已投天数是否显示 `今天` 或 `N 天`；更新时间是否只显示 `YYYY-MM-DD`？
   - 长轮次/待回看是否在状态色块下方单行展示，不撑高行？
3. 点击台账行，详情抽屉是否仍能查看完整 JD、渠道、岗位链接和纠错入口？
4. 设置页：
   - 提醒设置、数据与授权、安装指引、邮件测试与模板是否都在二级页签？
   - `/?panel=mail-admin`、`/?panel=plugin-connect`、`/?panel=plugin-sites` 深链是否落到正确页签？

### 2.2 窄屏 390px

- [ ] 侧边栏折叠为抽屉，菜单按钮可打开。
- [ ] Tab 焦点不逃出抽屉，Esc 可关闭并把焦点还给菜单按钮。
- [ ] 台账重排为卡片，页面级无横向滚动。
- [ ] 设置页页签可换行，无横向溢出。

### 对应自动化

```bash
npm run test:web
```

## 3. 模块 (c)：邮件抓取、识别与状态自动更新

### 3.1 先跑离线全链路基准

配置了外部模型凭据时：

```bash
MAIL_BENCH_ENV_FILE="/path/to/.env" MAIL_BENCH_JUDGE=flash npm run bench:mail-e2e
```

报告位置：

- `.tmp/mail-e2e-benchmark-report.md`
- `.tmp/mail-e2e-benchmark-report.json`
- `.tmp/mail-e2e-benchmark/<timestamp>/ledger.png`
- `.tmp/mail-e2e-benchmark/<timestamp>/reviews.png`

验收标准：

- [ ] 44 封（已知 10 / 未见 34）完成 11 轮同步。
- [ ] 召回、负样本拦截、公司、岗位、状态指标达到门槛。
- [ ] 状态回退、改期误判、自动入账残留待确认、终态轮次、街道地址等零容忍项均为 0。
- [ ] 报告中的模型为真实模型网关，不是假模型。

### 3.2 真实邮箱实测（QQ / Foxmail）

1. 在邮箱服务商后台开启 IMAP，生成**客户端授权码**（不是登录密码）。
2. 帮你理 → 设置 → 数据与授权 → 招聘邮箱，选择服务商，填入邮箱与授权码，同意只读授权。
3. 观察「已扫描 N / N 封」进度条从 0 到 100%，结束后临时进度文案应消失。
4. 检查「投递明细」：
   - 公司名、岗位名、城市是否合理；
   - 状态是否正确（已投递 / 笔试测评 / 面试 / 录用 / 拒绝 / 已结束）；
   - 邮件自动推进后，旧轮次是否清理；
   - 自动入账岗位是否仍重复出现在「待确认」。
5. 检查「待确认」：只应保留真正的字段/归属/终态歧义。

### 3.3 当前真实覆盖

- [x] QQ / Foxmail：已用真实公网邮箱完成 129/129 封扫描验收。
- [ ] 网易 163 / 126 / yeah.net：代码已支持，仍待真实授权码联调。
- [ ] 其他邮箱服务商不在当前支持范围。

### 对应自动化

```bash
npm run test:mail-progress
npm run test:intake
npm run test:mail-admin
npm run bench:mail-e2e
```

## 4. 模块 (d)：简历库、六维匹配与面试题

> **注意**：下方只验收简历库、手动编辑、六维匹配与面试题；AI 定向改写请在模块 (e) 验收。

### 4.1 简历库

1. 进入「简历库」。
2. 上传 PDF / DOCX，或粘贴文本。
3. 检查解析后的姓名、教育/经历/技能等字段；切换多个版本。
4. 设为当前简历，尝试手动文本编辑并保存。
5. 刷新页面，版本和历史编辑是否保留。

### 4.2 单岗位六维匹配

1. 进入「匹配分析」，选择一条已采集台账岗位和当前简历。
2. 运行单岗位匹配。
3. 检查六维卡片（能力/经验/行业/项目/教育/意愿等实际页面维度）是否可缩略/展开。
4. 检查匹配缺口与改进建议是否可读。
5. 对不准确的字段提交人工纠偏，确认结果持久化到报告。

### 4.3 面试题生成

- [ ] 在匹配报告中选择按缺口生成面试题。
- [ ] 面试题成功生成、可查看、刷新后仍存在。
- [ ] 旧的多岗位对比入口已下线；旧对比深链应安全落到单岗选择页，不发起多岗位对比请求。

### 对应自动化

```bash
npm run test:career-ai
```

## 5. 模块 (e)：AI 求职助手（v1.1.1）

### 5.1 入口与只读对话

1. 左侧导航打开「AI 助手」，确认标题、4 张快捷卡、当前简历/岗位上下文条。
2. 点击「查看本周投递情况」「找出长期没有反馈的岗位」，确认对话中只出现自然语言结论和轻量状态，不出现工具参数/三行工具结果卡片。
3. 打开「历史会话」，切换会话；切换简历或岗位，确认出现上下文边界提示，旧岗位 JD 不再用于新问题。
4. 点击一条岗位详情里的「问 AI 助手」，确认进入带当前岗位上下文的助手页。

### 5.2 受控写操作

1. 选中一个岗位，问「把状态改为面试」。
2. 确认对话出现**确认卡**（岗位、当前→目标状态、影响数量、取消/确认执行），确认前台账状态不变。
3. 点击「确认执行」，回到台账确认状态已变；刷新后仍保留。
4. 若记录在确认前被手动改过，确认结果应标注版本冲突并跳过该条，不能覆盖新值。
5. 问「按这个岗位的 JD 优化简历」：
   - 确认出现逐段改写对比、目标岗位、原简历版本、保存为新版本按钮；
   - 确认后简历库出现新版本，`parent_resume_id`/目标岗位可追溯；原简历文本不变；
   - 不勾选“设为当前”时，当前简历不被切换。

### 5.3 自动化

```bash
npm run test:agent
```

真实 OpenRouter 四场景（需要本地环境变量，不提交 key）：

```bash
OPENROUTER_API_KEY=... OPENROUTER_MODEL=google/gemini-2.5-flash \
  node tools/smoke-agent-openrouter.mjs
```

未配置 key 时脚本会输出 `.tmp/agent-openrouter-smoke.md` 的 **BLOCKED**，如实记录，不伪造通过。

### 5.4 验收标准

- [ ] 助手只读查询/对比/匹配/面试题正常，工具原始 JSON 不显示在消息里。
- [ ] 状态修改和简历改写必须先确认；确认后自动刷新台账/简历库。
- [ ] 版本冲突跳过且不覆盖。
- [ ] 简历改写只新增版本，原版本和原文本不被覆盖。
- [ ] 390px 助手页面无横向溢出，行动卡和信息卡可操作。

## 6. 模块 (f)：简历库「简历改写」工作台（v1.1.1）

1. 简历库顶部切换「简历改写」，确认目标岗位卡、简历版本卡、画像卡、JD 信息卡。
2. 从「投递明细」和「看过没投」分别打开二级岗位选择器，搜索并选择一个岗位；确认选中后上下文不混入旧岗位 JD。
3. 点击「开始定向改写」，确认出现左右对照：左侧原简历，右侧高亮改写；点击右侧段落可编辑，待补事实只提示不自动编造。
4. 修改新简历名称，点击「确认并生成 Word」，确认：
   - 新版本出现在简历库，原简历文本和版本不变；
   - 下载的 `.docx` 能在 Word/WPS 打开，包含 `word/document.xml`；
   - 「我的简历」版本行可以再次下载 Word。
5. 验证跨用户下载返回 404，草稿刷新/返回配置不会覆盖原简历。

### 自动化

```bash
npm run test:agent
npm test
```

模块 (f) 的服务端测试包含草稿结构、四级分类、原简历不变、非法 Word/跨用户下载；浏览器测试覆盖简历改写左右编辑、Word 下载和画像联动。
