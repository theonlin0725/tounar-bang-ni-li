# 二期本地验收清单

本轮没有发布线上。请先在本地/测试环境验收；真实数据改动前做 SQLite 一致性备份。不要把授权码、数据库或备份提交到 Git。

## 启动与自动回归

Node ≥24，在仓库根目录运行 `npm start`（本地默认端口 4310）。开发模式未配置 SMTP 时邮件写入 `data/outbox/`。可以使用默认白名单 `demo@tounar.local`，验证码从 `npm run otp:latest` 获取。真实邮箱请通过本地 `.env` / 安全设置配置白名单与发信，勿在聊天中发送授权码。

云环境浏览器准备和回归：

```bash
export PLAYWRIGHT_BROWSERS_PATH=/workspace/.cache/playwright-official
npx playwright install chromium
npm test
npm run test:e2e
npm run test:web
```

测试只写 `.tmp/tests/` 或系统临时库，并使用本地 outbox；不会把测试记录塞进用户台账。

## 待确认与邮件联动

- [ ] 登录后打开 `/?panel=reviews`，应直接进入待确认。退出后从该链接重新登录，仍回到待确认。
- [ ] 打开有候选卡片：能看到建议、把握度、原信收到日期；展开证据能看到主题、域名、正文片段。
- [ ] 没有候选时点击「选一条记录并更新」：可按公司/岗位搜索本人台账，选择记录并提交。已有投递时间不重复要求填写。
- [ ] 点击「不对，我来改」可改目标和状态；真实缺失投递时间时才显示时间输入。默认推断使用原信日期，并显示“≤ 日期（据邮件推断）”；关闭推断开关后须填写实际时间。
- [ ] 没有既有申请时，按邮件新建，公司/岗位/状态预填。提交成功后卡片消失，台账计数和状态更新，历史留痕。
- [ ] 10 秒内点击撤销，原状态和待确认项恢复。若另一个页面已修改记录，撤销应拒绝覆盖新版本。
- [ ] 批量确认仅处理 ≥80% 且有唯一系统目标的项；失败保留并标红。多个候选不猜选。
- [ ] 在两个页面制造并发修改，过期提交应提示“这条刚被更新过，已刷新，请再确认一次”，而非覆盖。
- [ ] 高把握唯一面邀自动更新；低把握拒信留待确认。详情能看到原信日期/主题及「这条改错了，撤回」。撤回写“邮件自动判定有误”历史。
- [ ] 台账重新获焦或等待 60 秒后自动显示邮件变更提示与高亮；「立即同步邮箱」受理后会查询结果，失败应显示原因。
- [ ] `/?app=<真实记录ID>` 可直接开详情；未登录时，登录后继续该深链。

以上交互已在隔离自动测试中验证。真实账号既有那十几条复核项仍需用户本地验收；本轮未对线上记录提交确认。

## 提醒邮件

- [ ] 提醒设置能独立选择“笔试/面试后 7 天 / 14 天 / 关闭”，默认 7 天；原已投 N 天设置保留。
- [ ] 一条原信对应一个进展段落，主题、顶部日期、落款、文本版与 HTML 版都显示原信收到日期；多条显示收信日期范围，推送时间仅在页脚。
- [ ] 阶段回看有：直接打开官网、确认看过没变化、打开台账详情三个入口。
- [ ] 有更晚预约面试时间时从该时间算起；笔试推进面试后，旧阶段回看失效；终态不再提醒。
- [ ] 明确确认没变化后再过 N 天才提醒；同条至少相隔 7 天。仅打开邮件不更新确认时间。

自动测试已覆盖 D+7 08:00 的真实本地 outbox 发信，不等于真实 QQ SMTP 送达或客户端排版验收。

## 插件采集与旧字段修复

- [ ] 导航/侧栏标题、加载中、整页最长文字不能成为岗位字段；缺失或低把握字段显示灰色待补充。
- [ ] SPA 换路由时不把旧标题配上新 URL；同 URL 切岗位也重新识别，安静约 800ms 后计可见停留时间。
- [ ] 更高把握的新采集字段能纠正旧机器值；人工字段不被覆盖。
- [ ] 使用 README 的 dry-run 命令先审阅旧字段修复清单。只有用户明确确认后执行 apply；不要直接对线上库运行。脚本会先备份并拒绝过期计划。
- [ ] 按站点证据表逐站验收 13 站、每站 2 个真实岗位，保存脱敏 HTML，登记 `tests/fixtures/sites/cases.json` 后重跑插件回归。

当前已有 8 站 16 页真实证据及离线回归；优先八家完成 6/8。CA 问题已在获批的正常 NSS 执行上下文解决。剩余阿里、百度、BOSS、牛客、拼多多共 10 页仍受入口或资源条件阻塞，用户暂不应用更多网络配置。不得关闭 TLS 校验、把错误页存作岗位快照，或把离线合成用例记成真实站点通过。
