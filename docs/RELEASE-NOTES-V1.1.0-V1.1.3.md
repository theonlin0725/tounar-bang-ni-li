## v1.1.0：AI 求职助手首版

**定位**：在 v1.0.0 的台账、邮件同步、简历匹配基础上，新增一个能查数据、能生成分析、能发起受控写操作的 AI 助手。

### 新增功能

- **AI 助手入口与会话**
  - 左侧新增「AI 助手」入口。
  - 支持欢迎卡、快捷任务、历史会话、当前上下文切换、SSE 状态、自然语言结论与引用链接。
  - 支持 390px 移动端卡片与输入区适配。
- **8 个助手工具**
  1. `search_jobs`：搜索岗位。
  2. `filter_applications`：筛选投递记录。
  3. `get_job_detail`：读取岗位详情/JD。
  4. `compare_jobs`：多岗位对比。
  5. `analyze_match`：单岗位六维匹配，复用/新建 `ai_reports(kind=match)`。
  6. `generate_interview_questions`：生成面试题并持久化。
  7. `update_status`：批量改投递状态，只生成待确认单。
  8. `rewrite_resume`：按目标 JD 生成逐段改写方案，确认后新建简历版本。
- **写操作确认机制**
  - 状态修改、简历改写先在对话中展示确认卡。
  - 用户明确确认后才落库；`update_status` 确认时逐条校验 `expected_version`，避免覆盖期间的其他修改。
  - 审计日志记录 `actor='agent_confirmed'`。
- **数据与接口**
  - 新增 `agent_sessions`、`agent_messages`、`agent_tool_runs`、`agent_pending_actions` 四张表。
  - `resumes` 增加 `parent_resume_id`、`target_application_id`、`rewrite_summary_json`。
  - `ai_reports` 增加 `interview_result_json`，并支持 `kind=match`。
  - 新增 9 条 Agent 路由：会话、上下文、消息、SSE 对话、确认/取消写操作等。
- **上下文与安全**
  - 支持切换简历、岗位上下文；切换岗位写入 `context_boundary`，避免旧 JD 污染新轮次。
  - 单轮最多 6 次工具调用。
  - 工具原始 JSON 只写入 `agent_tool_runs`，不进入对话消息；前端只展示轻量状态和最终结论。
  - 模型配置优先级：`AGENT_*` → `OPENROUTER_*` → `AI_*`；OpenRouter 携带 `HTTP-Referer` / `X-Title`。
  - 前端新增岗位详情、匹配报告的「问 AI 助手」快捷入口。

### 修改/增强

- `filter_applications` 新增 `applied_from`、`applied_to`、`inactive_days` 筛选参数。
- `ai_reports` 的 `kind` 约束加入 `match`；旧库通过重建表迁移，报告数据保留。
- 写操作从“直接改库”改为“确认卡 → 用户确认 → 服务端乐观锁校验”的流程。

### 修复

- 本版本以新增能力为主，没有单独的既有 Bug 修复项。

### 移除/替换

- **没有删除任何既有业务功能**。
- 本版本没有替换 v1.0.0 的核心台账、邮件同步、插件采集或简历匹配能力。

### 兼容性与边界

- 仅增量建表/加列，旧库可直接启动。
- 真实 OpenRouter 联调因开发环境缺少 `OPENROUTER_API_KEY` 标记为 BLOCKED；浏览器 E2E 使用确定性模型。
- 本版本**未包含**：独立求职画像、投递策略转化漏斗、单岗位自定义提醒天数、独立多轮记忆压缩。

### 验证

- `test:agent`：服务端 10+4+4+2 项 + Playwright 12 项通过。
- `npm test`：248 条中 247 条通过；仅既有云快照用例环境性波动。
- `test:web` 74/74、`test:e2e` 67/67、`test:career-ai` 51/51、`test:panel` 8/8、`test:netease-game` 60/60、`test:self-page` 6/6。

## v1.1.1：助手体验、求职画像与简历改写工作台

**定位**：把 v1.1.0 的助手从“能用”推进到“好用”，并补齐求职画像和独立的简历改写工作台。

### 新增功能

- **安全 Markdown 渲染与排版**
  - 新增 `web/assets/js/markdown.js`，支持标题、加粗、斜体、行内代码、列表、引用、代码块和安全链接。
  - 全程使用 DOM 节点构建，不使用 `innerHTML`；`<script>` 等输入按文本处理，避免 XSS。
  - 助手正文调整为 15px / 1.75 行高、780px 气泡宽度、中文无衬线字体栈。
- **精致操作确认卡**
  - 改为“请确认操作 + 双列键值表 + 风险提示条 + 右侧按钮”的结构。
- **求职画像**
  - 新增 `user_profiles` 表与 `GET/PUT /api/v1/profile`。
  - 新增 `update_profile` 工具：只生成待确认卡，确认后写入 `status=confirmed`。
  - 六维画像：职业发展方向、期望地点、薪资期望、工作方式、行业偏好、企业偏好。
  - 已确认画像注入单岗位匹配的报告上下文和模型 payload。
  - 助手欢迎卡、底部上下文条、匹配分析页显示真实画像状态；匹配页支持手动编辑和“用 AI 助手梳理”。
  - 插件连接成功并关闭网站授权后，若画像未确认，自动跳转 `/?panel=assistant&onboarding=profile`，可跳过。
- **二级岗位选择器**
  - 新增 `web/assets/js/views/job-picker.js`，助手和简历改写共用。
  - 第一级：全部岗位 / 投递明细（N）/ 看过没投（M）。
  - 第二级：搜索、状态/城市筛选、滚动触底分页。
  - 选择后继续走 `PATCH /agent/sessions/:id/context` 和 `context_boundary`，不混入旧 JD。
- **简历库「简历改写」工作台**
  - 简历库新增“我的简历 / 简历改写”二级页签。
  - 支持选择投递明细/看过没投岗位、简历版本弹窗、画像/JD 信息卡、补充要求。
  - 新增 `resume_rewrite_drafts` 表和 9 步结构化改写草稿。
  - 四级事实对齐：`supported_optimize` / `improvable` / `needs_user_fact` / `unsupported_blocked`。
  - 右侧高亮可编辑；待补事实只提示不编造；拦截内容不写入最终块。
  - 支持草稿 PATCH、确认保存，默认命名“原简历名_岗位名”。
  - 新增无依赖 OOXML Word 导出：`GET /api/v1/resumes/:id/export.docx`，强校验 owner，文件保存在 `DATA_DIR/resumes/...`。
  - 简历库版本行提供 Word 下载入口。

### 修改/增强

- **SSE 与错误处理**
  - SSE 增加单次 socket 超时关闭、8 秒心跳，请求校验提前到响应头之前。
  - 服务端异常会落盘一条 `meta.is_error` 的助手消息并带 `retry_text`；前端显示错误气泡和“重试本轮”。
- **对话区布局**
  - 改为固定视口 Flex 布局，消息区独立滚动。
  - 状态条原地更新，不再因 `status` 事件清空历史 DOM。
  - 输入框聚焦使用 `preventScroll`，避免页面跳动。
- **画像与匹配**
  - 单岗位匹配读取已确认画像，影响地点、薪资、工作方式、方向、行业、企业偏好等维度。
- **数据兼容**
  - `resumes` 增加 `export_docx_path`、`layout_meta_json`。
  - 旧 `agent_pending_actions` 通过重建表加入 `update_profile` 动作类型，历史 pending/confirmed 行保留。

### 修复

- 修复“按 JD 改写简历”等重任务静默消失、长时间无回答的问题：异常现在必须有可见回复和重试入口。
- 修复点击回答下方快捷提示词后页面自动跳回顶部的问题：改为独立滚动容器 + 原地更新状态。
- 修复画像状态假展示：未建立/已建立现在读取真实数据。
- 修复旧岗位下拉只有近期少量记录、无法分类浏览的问题：升级为二级选择器。

### 移除/替换

- **没有删除任何业务功能**；以下旧实现被替换：
  - 旧平铺岗位 `<select>` → 二级岗位选择器。
  - 旧纯文本/按换行拆分的消息渲染 → 安全 Markdown 渲染器。
  - 旧 3 秒 toast 错误提示 → 消息流错误气泡 + 重试。
  - 旧整页 `window` 滚动布局 → 固定视口 Flex + 独立滚动。
  - 旧简易确认卡 → 双列键值表 + 风险条确认卡。

### 兼容性与边界

- 仅增量建表/加列；旧库可直接升级。
- Word 为 ATS 友好的标准可编辑 `.docx`，不承诺任意 PDF 多栏/绝对定位的像素级还原。
- 新简历版本初始为 `parsed`；勾选“设为当前”后需重新分析才能用于匹配。
- 真实 OpenRouter 联调仍需 `OPENROUTER_API_KEY`。

### 验证

- `test:agent`：25 项服务端 + 24 项 Playwright 通过。
- `test:web` 74/74、`test:e2e` 67/67、`test:career-ai` 51/51。
- `npm test`：除既有云快照环境波动外全部通过。

## v1.1.2：AI 助手稳定性与回答质量

**定位**：解决真实模型调用中的“空回答、截断、格式不兼容、工具步数用完就拒答”等稳定性问题，同时提升简历改写的连贯性和 token 效率。

### 新增功能

- **只读工具 `get_resume_detail`**
  - 可按当前上下文或指定 `resume_id` 读取完整简历，供助手做更准确的分析。
- **受控写入工具 `update_job_fields`**
  - 可修改公司、岗位、城市、批次、链接、JD。
  - 先生成确认单，确认时复用 `correctApplication()` 和 `expected_version` 乐观锁。
- **模型网关配置**
  - `AGENT_MAX_TOKENS`：普通对话默认 2800，改写显式 6000。
  - `AGENT_FALLBACK_MODEL`：主模型失败时的备选模型。
- **结构化脱敏诊断日志**
  - 记录 provider/model/HTTP/finish_reason/content_len/reasoning_len/tool_calls_len/attempt/latency/error_code，不打印 key 或用户正文。
- **前端常驻欢迎区**
  - 首轮对话后顶部欢迎、画像条和 4 张快捷任务卡保持常驻。
  - 画像未建立显示暖琥珀提示和“现在开始”；已建立显示青绿画像条和“修改画像”。
  - 画像确认后胶囊实时切换为“画像：已建立”。

### 修改/增强

- **模型网关兼容性**
  - 兼容 OpenRouter 数组分片 `content: [{type:'text', text}]`。
  - 处理 HTTP 200 内嵌 `{error}`，按鉴权/可重试分类。
  - 识别 `finish_reason=length` + reasoning 吃光正文的 `AGENT_REASONING_TRUNCATED`，自动提高 token 预算并重试。
  - 支持 `response_format: {type:'json_object'}`；上游 400 不支持时自动去掉并重试。
  - 可重试错误最多重试 2 次，退避 600ms / 1800ms。
- **编排器**
  - 达到工具步数上限时，不再输出“请缩小范围”；改为以 `tools: []`、`tool_choice: 'none'` 再调用一次模型，强制基于已读取的工具数据总结。
  - 空内容兜底重试/总结，最终失败才返回明确错误。
  - system prompt 鼓励并行发起多个只读工具，减少重复轮次。
- **简历改写工作台**
  - `sourceBlocks()` 从逐行碎片改为自然段/经历条目聚类，典型简历块数明显减少。
  - 改写输出改为 Delta 模式：模型只返回改动或需标注的 block，未提及 block 自动保留原文并标记 `unchanged`。
  - 四级护栏继续生效：`needs_user_fact` 不自动编造，`unsupported_blocked` 不写入生成内容。
  - JSON 解析失败自动修复提取，再失败追加纠错提示重试一次。
- **数据兼容**
  - `agent_pending_actions` 的动作类型加入 `update_job_fields`；旧库自动重建表，历史记录保留。

### 修复

- 修复 OpenRouter 数组分片、HTTP 200 内嵌错误、reasoning 截断导致的空回答/无效回答。
- 修复工具步数达到上限后直接拒答、不总结已读取数据的问题。
- 修复空内容没有兜底、直接报错的问题。
- 修复首轮对话后欢迎区和快捷任务卡消失的问题。
- 修复简历改写逐行碎片、输出体积大、未改动内容被重复抄回的问题。
- 修复改写 JSON 解析失败后直接失败的问题。

### 移除/替换

- **没有删除任何业务功能**；以下旧行为被替换：
  - 工具步数上限的硬编码“请缩小范围”拒答 → 强制无工具总结。
  - 首轮对话后隐藏欢迎/快捷卡 → 常驻显示。
  - 简历改写整份返回 → Delta 增量返回，未提及块自动保留原文。

### 兼容性与边界

- 新增 `AGENT_MAX_TOKENS`、`AGENT_FALLBACK_MODEL` 配置；旧配置仍可使用。
- 没有新增 HTTP 路由；工具扩展复用既有 Agent 路由和确认机制。
- OpenRouter 真实模型可能受账号限流影响；自动重试和诊断日志已覆盖，但仍需关注实际额度。
- Word 为 ATS 友好标准 `.docx`，不承诺复杂 PDF 的像素级还原。
- 改写新版本初始为 `parsed`，设为当前后需重新分析才能用于匹配。

### 验证

- `test:agent`：32 项服务端 + 26 项 Playwright 通过。
- 真实模型稳定性实测 10/10 通过，0 次 `AGENT_INVALID_RESPONSE`：5 类对话、3 次真实简历改写 + Word 导出。
- `test:web` 74/74、`test:e2e` 67/67、`test:career-ai` 51/51，其他面板/网易/自身页面/入账/邮件套件通过。

## v1.1.3：简历改写质量、进度与助手滚动优化

**定位**：解决 PDF 简历提取后的断行/碎片问题，把改写升级为“先分析 JD 要求、再分批 Delta 改写”的两阶段流水线，并把长耗时改写改成可见进度。

### 新增功能

- **简历反断行与块归并**
  - 新增 `normalizeResumeBlocks()`：识别模块标题、经历抬头、项目符号和“小标题：”边界。
  - 续行按中英文规则无缝拼接，清理 PDF 提取产生的孤立空格。
  - 真实 2049 字 PDF 简历实测归并为 28 个完整块，无“承接上一条”、无中文残句换行。
- **两阶段 9 步改写流水线**
  - 阶段一：读取 JD/简历，提取四类要求：`hard_requirements`、`core_competencies`、`plus_items`、`other_requirements`。
  - 阶段二：按 Delta 模式逐批对齐改写；超过 18 块自动分批，未提及块保留原文。
  - `supported_optimize` 要求实质表达升级；`needs_user_fact` 保持原文并提示；`unsupported_blocked` 严格不写入生成内容。
- **异步进度**
  - `resume_rewrite_drafts` 增加 `progress_percent`、`progress_label`。
  - POST 立即返回草稿，后台异步推进 15% → 40% → 75%/批次 → 95% → 100%。
  - 前端每 800ms 轮询，显示青绿进度条、百分比和阶段文案；成功后自动切换到左右对照，失败显示错误和“重新生成”。
- **左右对照与 JD 概览**
  - 改为成对行 Grid（`minmax(0,1fr)` × 2），移动端切为上下排列。
  - 补齐 `min-width:0 / overflow-wrap:anywhere`，修复右栏裁切。
  - 右栏使用轻量前缀/后缀 diff `<mark>` 高亮改动；聚焦时转为纯文本编辑，并提供“还原原句”。
  - 顶部新增 JD 四类要求概览条；报告继续展示缺口和四级计数。
- **助手滚动优化**
  - `.tn-assistant-welcome` 移入 `.tn-assistant-thread` 滚动容器顶部，不再固定占据上半屏。
  - 对话消息滚动时欢迎区自然滚出，回顶部仍可点击快捷卡。

### 修改/增强

- 改写流水线复用 v1.1.2 的模型网关重试、JSON 修复、数组分片和 reasoning 截断适配。
- 长简历自动分批，降低单次输出体积和截断风险。
- 进度条与左右对照联动：完成后自动收起进度条并平滑滚动到结果区。
- 右栏从“整块刷绿底”改为“轻量 diff 标记”，更容易看出具体改动。

### 修复

- 修复 PDF 简历提取后的“承接上一条”、中文残句换行和孤立空格。
- 修复右栏内容被裁切、长 URL/长英文单词溢出。
- 修复助手欢迎区固定占据上半屏、对话窗口过矮的问题。
- 修复长耗时改写没有可见进度、用户不知道是否卡死的问题。
- 修复改写失败后没有明确错误和重新生成入口的问题。

### 移除/替换

- **没有删除任何业务功能**；以下旧行为被替换：
  - 固定在上半屏的欢迎区 → 移入滚动容器，随对话自然滚走。
  - 右栏整块绿底高亮 → 轻量 diff `<mark>` 高亮。
  - 同步等待改写完成 → POST 立即返回 + 后台进度轮询。

### 兼容性与边界

- `resume_rewrite_drafts` 仅增量增加 `progress_percent`、`progress_label`；旧草稿默认 `100%`，不影响历史数据。
- 没有新增 HTTP 路由或 Agent 工具；沿用既有草稿、确认和导出接口。
- 长简历分批仍依赖模型可用性和账号额度；失败时保留明确错误和“重新生成”入口。
- Word 为标准 ATS 友好 `.docx`，不承诺复杂 PDF 多栏/绝对定位的像素级还原。
- 改写新版本初始为 `parsed`，设为当前后需重新分析才能用于匹配。
