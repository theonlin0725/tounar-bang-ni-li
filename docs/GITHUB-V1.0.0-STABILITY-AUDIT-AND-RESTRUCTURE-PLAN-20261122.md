### 1.3 为什么目前看着像“不稳定/看不懂”？——4 个真实问题与诚实边界

1. **GitHub 门面严重滞后（观感混乱的主因）**：
   - 远端默认分支仍指向旧分支 `origin/codex/beta4-local-review-20261103`，最新代码藏在临时分支 `codex/model-gated-local-review` 下；
   - 根目录 `README.md` 仍停留在 11 月初（写着 `beta4`、`插件 0.2.1`、`npm test 150 项`、`跨板块勾选 2–6 个岗位对比`、`≤ 日期（据邮件推断）`），与 `v1.0.0` 真实功能严重脱节；
   - `docs/` 目录平铺了近百份历史开发 prompt、中间排查和旧阶段交付报告，缺乏清晰入口。
2. **存在 2 条既有环境性失败，容易误导自测者**：
   - `npm test` 当前为 **226 / 228**，仅既有 `cloud-persistence` / `cloud-persistence-http` 两个云快照单测受环境波动失败（与本轮三大功能无关，但未在 README 说明会让首次跑测试的人以为版本坏了）；
   - `test:plugin-backend` 的随机不可达 origin 断言及无头 Playwright 扩展 service worker 存在环境限制。
3. **多邮箱真机覆盖不均衡**：
   - 代码层支持 QQ / Foxmail / 163 / 126 / yeah.net，但**仅 QQ 邮箱做过真实公网授权码全链路验收**；网易 163 / 126 / yeah.net 尚未完成真机联调。
4. **【关键需求纠偏】关于自测模块 `(d) 简历的改写`**：
   - **当前 `v1.0.0` 代码库尚未实现“按目标 JD 自动逐段改写简历并生成新版本”功能**。
   - 当前已落地的简历相关能力为：**简历上传与解析（PDF/DOCX/粘贴文本）→ 多版本简历库管理与手动编辑 → 单岗位六维匹配分析（含缺口诊断与改进建议）→ 匹配纠偏 → 面试题生成**。
   - 因此在 `tounar-1.0.0` 的 README 与内测指引中，模块 (d) 必须如实标注为**「简历库管理、单岗位六维匹配分析与面试题生成」**，而将**「AI 按 JD 定向改写简历并生成新版本」**明确归入「未开发功能」，避免产品按不存在的功能验收。

### 1.4 稳定性定级结论

> **`d6670d1`（`v1.0.0`）可以作为「本地自测稳定版」对外提供给产品和 AI 助手部署体验**，核心业务链路与回归结果均已完整带齐；当前最紧迫的工作不是推倒重来，而是**切出清晰分支 `tounar-1.0.0`、彻底重构 GitHub 首页与内测文档、并如实标明上述 4 项已知边界**。
