# 岗位识别：文字优先，公司名看图兜底

在 Dify 工作室选择「导入 DSL」，上传 `job-company-vision.workflow.yml`，安装并启用官方 DeepSeek 和 Tongyi 模型插件。在「设置 → 模型供应商」分别配置 DeepSeek 官方凭据、阿里云百炼凭据及对应地域和工作空间端点（如需）。不要把密钥写进 DSL。

文字节点通过 DeepSeek 官方接口使用 `deepseek-flash`，不开启视觉。兜底节点通过阿里云百炼使用 `qwen3.6-flash`，开启视觉并引用 `brand_crop`，关闭思考，输出上限为 256 tokens。两个节点均不依赖 OpenRouter。

在测试运行中填写 `page_text`，可选上传一张 PNG/JPEG 品牌区域裁剪图（不要上传全页、登录头像或个人资料）。文字分支返回 `job`、`extraction`、`company_name`、`company_evidence`、`company_source`、`needs_review`；视觉分支的对应输出使用 `vision_` 前缀，满足 Dify 的输出变量全局唯一要求。视觉输出只作待确认的建议，不回写岗位。无法确认多个雇主时直接待确认；文字模型请求失败或无有效 JSON 时运行失败，不调用视觉。

| 测试输入 | 预期 |
| --- | --- |
| 有明确的招聘主体文字，即使传了图 | `text`，运行轨迹没有视觉节点 |
| 公司名只在品牌裁剪图，文字有具体岗位和职责 | 运行一次视觉节点；可读时 `vision`，仍待确认 |
| 只出现招聘平台名，没传图 | `none`，待确认，不调用视觉 |
| 文字有多个可能雇主且无法归属 | `none`，待确认，不调用视觉 |
| 列表页或文字模型调用失败 | 不调用视觉 |

## 与帮你理主应用的关系

此工作流只保留作独立演示。帮你理插件不使用 Dify：后端直接调用 DeepSeek 做文字提取；配置 `JD_VISION_*` 后，公司名缺失时再通过千问识别已获授权岗位页的滚动全页截图。视觉结果只作核对建议，不作为文字证据入库。
