### 全站字体｜对齐参考侧栏

参考图能看出中文无衬线字形，无法凭截图唯一确定字体名称。按用户偏好，以**微软雅黑**作为首选，中英文标签及数字沿用同一套 UI 字体。此图只用于字体比对，导航内容仍执行本单的设置与对比下线要求，无需增加图中的 AI Assistant 或英文翻译。

- **字体入口。** 在 [app.css](../web/assets/app.css) 统一现有 `--font-sans` 为 `"Microsoft YaHei", "微软雅黑", "PingFang SC", "Noto Sans CJK SC", "Noto Sans SC", system-ui, sans-serif`。使用本机已安装字体。Windows 优先微软雅黑，缺少它的 macOS/iOS 优先苹方，其他设备按栈回退。[独立邮件自测指南](../web/assets/mail-guide.css) 引用同一份字体定义。
- **覆盖范围。** 当前正文已有无衬线栈，但页面大标题、匹配结论、统计数字等显式使用 Georgia／宋体。逐处将用户界面文案切至统一字体，包括侧栏、登录与提醒落地页、台账、简历库、匹配分析、设置和邮件管理；按钮、输入框、下拉框、文本域及文件选择按钮检查字体继承。简历修改建议等自然语言编辑区也使用 UI 字体。代码、模板源码等技术内容可用等宽体；静态图标及邮件正文预览保留原素材或模板排版。
- **字号与层级。** 以 CSS 像素为准：侧栏主入口 14px，常态 400、选中 600；徽标数字 12px，启用等宽数字；正文 14–16px、行高 1.5；小节标题 16–18px/600，页面标题 22–24px/600。图标、文字与徽标按行垂直居中。原侧栏选中底色和焦点轮廓继续表达状态。尺寸是本次实施建议，参考图的像素缩放不作为取值依据。

## 2. 简历库｜默认看版本，需要时看内容

**首屏顺序**　页标题“简历库” → 主操作“上传新版本”及次操作“粘贴文本” → 当前版本行（文件名、时间、分析状态） → 画像摘要 → 其他版本列表。删除“1. 简历”的序号、页首使用说明、正常状态的“模型服务……”和简历页“返回台账”；侧栏仍可回台账。格式与 5 MB 限制放到文件选择处，文本框只在点“粘贴文本”后出现。保留上传、解析失败、缺少模型、证据不足等与当前操作有关的提示和可用的恢复动作。

- **缩略画像。** 默认显示“主要技能”“工作／项目经历”两条摘要，各展示最多两个已有名称及剩余条数；其他有内容的“行业经验、突出优势、关键限制”收在“更多画像”内。展开一组才显示明细，每项可查看对应原文。沿用原文字段，旧画像中教育与工作混在一起时使用中性的“经历”标签，不能把学历标成工作经验。空画像展示下一步，不能生成装饰性标签。桌面可双列，手机单列。
- **版本管理。** 支持连续上传多个版本，同名文件也各有 ID。文件控件可一次选多份，按选择顺序逐份调用已有接口，显示每份的成功或失败，只重试失败项。默认沿用“最近创建的版本为当前”；分析失败保留该版及重试入口，允许用户切回已就绪版本。历史行有“查看”和“设为当前”，预览不改变当前；“修正文本”“重新分析”绑定画面上明确标出的版本 ID。修正继续使用现有接口，避免从 800 字预览回填并截断全文。
- **最小后端补齐。** 复用详情 `GET /api/v1/resumes/:id`，增加按登录账号设置当前版本的操作，事务内验证归属、切换，利用现有唯一索引，重复点击幂等。列表新增稳定游标和“加载更多”，兼容现有列表返回格式；第 21 份及更早的版本应可找回。区分正在预览的 ID、账号当前 ID、正在分析的 ID，异步结果按 ID 合并。切换当前版本使用单独的状态变更，避免把选择时间当简历内容版本。
- **与匹配联动。** 开始匹配或推荐前显示使用的当前简历。变更当前版本后新分析读取该版；旧报告按生成时快照展示原文件名、版本、证据。浏览、展开、切换版本均不隐式发起 AI 分析。

## 3. 设置｜一个主入口，按任务分栏

侧栏五项收成一个 **设置**。已登录设置页使用四个子页签：**提醒设置、数据与授权、安装指引、邮件测试与模板（仅管理员）**。默认打开提醒设置；窄屏页签可换行，保持文字完整。下载插件是“安装指引”内可直接点击的按钮，旁边显示版本，下面是现有安装步骤。

| 新位置 | 必须仍能完成的任务 |
|---|---|
| 设置 → 提醒设置 | 读取、编辑、保存偏好，预览提醒。复用原验证和错误反馈。 |
| 设置 → 数据与授权 | 插件设备、配对与站点授权、QQ 邮箱连接和同步、撤销、数据删除及二次确认。保留定时器清理、异步取消和状态刷新。 |
| 设置 → 安装指引 → 下载插件 | 直接下载当前目标发布包，保留分享码传递。登录页的下载/指引及设备升级提示共用同一个下载源。让发布过程由 manifest 或发布清单提供版本，校验文件名、页面标签和包内版本一致。 |
| 设置 → 邮件测试与模板 | 复用原管理界面、预览、试发和权限检查。普通用户看不到入口，直接访问仍由后端检查权限。 |

建议用 `/?panel=settings&tab=reminder|data|install|mail-admin` 表达页签；原 `/?panel=settings` 进入默认页，`/?panel=mail-admin` 进入对应管理页。保留 `plugin-connect`、`plugin-sites` 的配对/授权意图，`/r/<token>` 的提醒落地，以及登录前的安装入口。把设置弹窗内容抽成可复用主体，侧栏显示正式设置页；台账内“去处理”可继续就地打开同一主体并返回原筛选和滚动位置。避免设置页和弹窗各维护一份表单。原链接、刷新、浏览器前进后退、移动端选中态与焦点都要测。同步改动实际面向用户的安装/邮件自测操作指引。

## 4. 匹配分析｜岗位、历史、结论和依据

### 选岗与历史（图 4、5）

1. 删除匹配页头两段划线说明和正常模型服务横条。保留“单岗位匹配分析”，副文案改为图中指定的 **“帮你选择合适的岗位”**。搜索框和岗位选择器同排，窄屏上下排列。没有简历、缺 JD、分析中、失败或需要重试时仍显示针对该状态的提示。
2. 选中后显示“公司 · 岗位　城市　原岗位　**查看历史报告**”。取消搜索框右侧“报告已生成……”和常驻历史下拉及说明行。保留首次分析按钮、已有报告及报告下方重新分析入口。点击历史后才展开列表，列出日期、所用简历、结论或失败状态；点一份查看快照，再点可收起。快速切岗时忽略旧响应。按钮、翻页和浏览历史只发读取请求。
3. 历史查询先按账号、报告类型和岗位筛选，再稳定排序分页；避免其他岗位的近期报告挤掉此岗位历史。复用已有报告详情、补充证据和重跑关联。当前台账名称和旧快照标题不同时，当前岗位行显示新名称；历史报告头标明“生成时岗位”，报告编号和技术版本收入“报告信息”。旧结论保持可追溯。
4. 首屏两张结论卡、总体建议、硬门槛阻断、“查看门槛”、六维默认收起及五项下一步操作沿用上次交付。此次简化主要发生在选岗区和总结区。[上一轮验收](CAPTURE-AND-MATCH-UX-REPAIR-RESULT-20261120.md)

### 优势与差距（图 6）

- 将双列长清单改为四个可展开分组：**技能、工具、经历、项目**。组头显示有内容的计数，例如“工具　优势 2 · 明确差距 1 · 待补证 1”。首屏仅见组头；点开一组后，以三个小标题分开显示“优势”“明确差距”“待补证”，每项是一条短判断。硬门槛、行业、地点和成果中无法准确归到四组的事项，保留在“其他岗位条件”内，仍能回到对应六维。空分组使用简短空态。
- 按**单个事项**归类，原始维度和证据引用保留。技能是可执行的能力，工具是具体软件、语言或平台；经历是职责与业务场景，项目是具体作品、交付物或成果。同一结论出现多次只计一次，保留所有证据入口。只有维度级证据时标明“维度依据”，不能声称引文精确支撑某一条。新数据可增添可选分类及证据标识；老数据可保守归到组合项或其他条件。打开页面不为分类调用模型。
- 分类例：“未见 C++ 实践”放入**工具／待补证**，提供“补充经历”；同份报告若有另一条已核验的硬冲突，单独列为明确差距。“用 SQL 复盘玩法数据”仅在与该岗位要求有关且有用户原文时列为优势。从总结点“查看依据”，打开对应六维并定位引文；从“补充经历”进入现有预览、确认、重新分析流程。
- 新报告优先用逐项门槛结果和可核验的岗位／用户证据生成分类；仅未提及、用户偏好未知均属于待补证。旧快照如已有歧义，只在阅读层注明待核实，保留原始判断供查看。分组计数与展开条目逐项对得上。

### 未投递岗位推荐（图 7）

标题改为 **未投递岗位推荐**，去掉“3.”。保留推荐按钮、整体建议、排名、相对匹配度和地点。每个岗位内将 **推荐理由、匹配优势、主要缺口** 分为三个小卡：分别用中性底、淡绿色、浅琥珀色，标题加粗，搭配文字或图标。桌面空间充足时三列，窄屏单列；每卡先列两条，有更多才出现“展开其余 N 条”。空数组使用“暂无已核实内容”。下一步行动与岗位链接统一放在卡片底部。

复用现有推荐接口、候选条件、排序与 JD 不足列表。排名与绝对匹配度分别呈现，排名第一的“相对匹配低”依然显示低。不要因删除多岗对比而删除扫描全部未投递候选、分页外岗位、排名或推荐卡。

## 5. 下线岗位对比｜完整移除创建路径

- 台账“看过没投”和“投递明细”均有对比专属的全选、行勾选和跨页选择。移除选择列、选中状态、对比条及专属样式，修正表头、空行和移动端对齐。待办筛选框、状态编辑、打开岗位、补充信息、转已投、归档和邮件处理均独立保留。
- 删除匹配页对比区、`selectedIds` 批量读取、`runCompare`、`autorun=compare` 和所有重绘分支。旧 `?panel=career&apps=…&autorun=compare` 安全落到单岗匹配选岗页；去除对比参数，模型调用零次。保留岗位详情的单数 `?panel=career&app=<id>`。推荐和单岗共用的渲染函数按调用方核对后处理。
- 按“删去岗位对比功能”退役新建对比的 API：已登录请求旧 `POST /api/v1/ai/compare` 返回明确退役状态（建议 410），无模型调用、无报告写入。历史 compare 报告维持本人只读、账号删除仍可清理；不迁移删除已有记录。保留 match、recommend 及读取历史的接口契约。

## 6. 下游必跑回归与签收

先在隔离环境记录基线并准备两个普通账号、一个管理员，至少两份不同简历、一个有多份报告的岗位、已投/未投/已归档及 JD 缺失岗位。按简历版本、设置、报告阅读、对比下线分批开发，每批更新对应断言。最终在同一候选提交和同一实际待发布包上运行以下用例。
