# 简历改写质量、进度条与 AI 助手滚动排版优化方案（v1.1.3）

**日期**：2026-11-23
**基线分支**：`tounar-1.1.2`（提交 `af61ae6`，**严禁改动已封板的 `tounar-1.0.0` / `v1.0.0`**）
**核心目标**：解决真实长 PDF 简历自测中暴露的 5 个核心痛点——① PDF 物理断行导致句子被砍成两半、“承接上一条”且几乎没实质润色；② 右侧改写卡片裁切与左右排版错位；③ 点击生成后无实时进度条、偶发生成失败；④ 严格落地 9 步工作流与 JD 四类要求拆解；⑤ AI 助手顶部欢迎与快捷区改为随对话自然滚动（**不要固定吸顶**）。全程不影响任何已有功能，并通过全量回归测试。

---

## 1. 实测问题根因定位（结合真实截图）

1. **简历被 PDF 软换行砍成半句话、右侧充斥“承接上一条”且润色太弱**：
   - `sourceBlocks()` 按 `\n` 拆分原 PDF 文本时，没有先合并同一条项目符号（`·` / `•`）内的跨行续行，导致原本完整的一句话被劈成 2–3 个残缺片段（如 `归因数` / `据异动`、`总结“发` / `情”`）；
   - 模型拿到残缺半句只能标注“承接上一条”，既没法按 JD 关键词重组整句表达，又把右栏拆出一堆碎片卡片。
2. **左右对照排版难看且右栏被截断**：
   - 右栏卡片缺少 `min-width: 0` / 自动换行约束，长句在右边缘被裁切；左右两侧没有按“同一条完整经历”成对行对齐，且整块涂绿看不出具体改了哪些词。
3. **缺少实时进度条，且长简历偶发生成失败**：
   - 点击「开始定向改写」后按钮变灰干等，没有任何阶段进度反馈；
   - 单次请求把 9 步（JD 解析 + 全量简历块对齐 + 改写 + 报告）塞进一次巨型 JSON 输出，面对长 PDF 简历 + 长 JD 时仍易触达输出上限或 JSON 截断而失败。
4. **AI 助手顶部快捷区占据大半个屏幕**：
   - 当前 `.tn-assistant-welcome` 放在滚动容器 `.tn-assistant-thread` 外部上方，导致它固定占据上半屏、对话窗口被挤压得非常矮；用户需要的是**保留在最顶部但随对话自然滚走（不固定吸顶）**，想点时滑回顶部即可。

## 2. 简历库「简历改写」升级方案

### 2.1 简历反断行合并器：按完整句子/条目切片（`server/src/modules/career-ai/rewrite-workbench.js`）

在 `sourceBlocks(resumeText)` 之前新增 `normalizeResumeBlocks(resumeText)`：
- **识别真实结构边界**：
  - 模块标题行（`基本信息 / 教育背景 / 实习经历 / 工作经历 / 项目经历 / 校园经历 / 专业技能 / 个人总结` 等）；
  - 经历抬头行（如包含起止时间 `2024.06 - 2025.08`、`2025/06 - 至今` 等）；
  - 新条目开头（以 `·`、`•`、`●`、`- `、`* `、`1.`、`①` 等项目符号或明显“小标题：”开头的行）。
- **合并跨行残句（彻底消灭无意义断句）**：
  - 凡是不属于上述新边界的续行，自动拼接回上一条经历的末尾（中文字符间无缝拼接、不插多余空格；英文单词间补 1 个空格）；
  - 清理 PDF 提取产生的孤立多余空格（如 `2025.06 - 2025.08     广州钛动科技...` 规整为单空格分隔）；
  - 确保交给模型的每一个 `block` 都是**一条完整、独立的句子或项目要点**，严禁把一句话砍成两半，Prompt 中明确禁止输出“承接上一条”。

### 2.2 两阶段 9 步工作流 + JD 四类要求拆解 + 实质性润色

将原本容易失败的单次巨型 JSON 调用，升级为**高稳定两阶段流水线**（严格执行 9 步，且为前端进度条提供真实阶段节点）：

1. **阶段一：读取与结构化解析（步骤 1–4）**
   - 步骤 1：读取目标岗位完整 JD；
   - 步骤 2：读取用户选择的简历版本并执行 `normalizeResumeBlocks` 整句清洗；
   - 步骤 3：调用模型提取 **JD 关键词与四类能力要求**：
     - `hard_requirements`（**硬性要求**：学历、专业、年限、必备工具/语言等）
     - `core_competencies`（**核心岗位能力**：直接决定录用的关键业务与技能要求）
     - `plus_items`（**加分项**：优先条件、加分背景或工具）
     - `other_requirements`（**其他岗位要求**：沟通协作、抗压、出差等通用素质）
   - 步骤 4：结构化汇总简历中的技能、经历与项目块。
2. **阶段二：逐条对齐、实质性润色与报告生成（步骤 5–9）**
   - 步骤 5：对齐 JD 四类要求与简历整条经历；
   - 步骤 6：识别能力差距；
   - 步骤 7：生成逐段修改建议，**强制四级分类与事实红线**：

| 对齐类型（`alignment_type`） | 系统处理方式 |
|---|---|
| `supported_optimize`（已明确存在的经历） | **必须做实质性表达升级**：围绕 JD 核心关键词与岗位术语，按「痛点/目标 → 动作/方法 → 量化结果」重写整条句子，使其显著贴合目标 JD，**严禁原句照搬，也严禁编造任何未出现的数字/公司/项目** |
| `improvable`（可以优化的经历） | 提供具体的整句改写建议与改动原因，供用户一键采纳或微调 |
| `needs_user_fact`（需要用户补充事实） | 保持原文不动，进入「待补充状态」提示用户补充缺失的关键数据或职责 |
| `unsupported_blocked`（当前没有证据支持的内容） | **硬拦截，绝不允许写入改写稿**，仅在差距报告中提醒 |

   - 步骤 8：组装岗位专属简历草稿；
   - 步骤 9：生成结构化简历改写报告（含 JD 四类要求覆盖统计、关键词命中表、能力差距、四级分类计数）。
3. **彻底解决长简历偶发生成失败**：
   - 两阶段拆分后单次输出 Token 大幅下降；
   - 若简历正文块超过 **18 条**，阶段二自动按模块切分为 2 批顺序/并发改写再汇总，避免单次大 JSON 截断；
   - 复用 `llm.js` 的 OpenRouter 数组分片/reasoning 兼容、JSON 修复与 2 次退避重试；若某批次仍失败，返回明确可读错误码与一键 `[重新生成]` 按钮。

### 2.3 真实分阶段生成进度条（`server/src/routes/index.js`、`web/assets/js/views/resume-rewrite.js`）

- **后端实时进度通道**：
  - 将创建改写草稿接口升级为异步任务 + 进度查询（或 SSE 流）：在 `resume_rewrite_drafts` 增量补充 `progress_percent INTEGER` 与 `progress_label TEXT`（或使用 `GET /api/v1/resumes/rewrite/drafts/:id/status` 每 800ms 轮询，彻底规避长连接超时）；
  - 真实推进 4 个阶段进度：
    - `15%`：步骤 1–2 · 正在读取目标岗位完整 JD 与原简历…
    - `40%`：步骤 3–4 · 正在解析 JD 四类要求（硬性/核心/加分/其他）与整理简历整句…
    - `75%`：步骤 5–7 · 正在逐条对齐 JD 关键词并润色项目经历…
    - `95%`：步骤 8–9 · 正在生成岗位专属草稿与改写报告…
    - `100%`：生成完成！
- **前端进度条 UI**：
  - 在「开始定向改写」按钮正下方渲染柔和青绿进度条 + 百分比数字 + 当前阶段文案；生成完成后自动收起进度条并平滑滚动到左右对照结果区；失败时进度条转为红色错误提示并保留 `[重新生成]` 按钮。

### 2.4 左右对照排版与内联差异高亮升级（`web/assets/js/views/resume-rewrite.js` & `app.css`）

- **整条成对行对齐（Paired Row Grid）**：
  - 改为 `display: grid; grid-template-columns: minmax(0, 1fr) minmax(0, 1fr); gap: 16px;` 按**同一条完整经历**逐行左右对齐（标题行横跨或左右对齐），彻底修复右栏文字被截断问题（全部加 `min-width: 0; overflow-wrap: anywhere; word-break: break-word;`）。
- **内联词级/句级高亮，一眼看出改了哪里**：
  - 右栏不再整块刷满绿底导致看不出修改点，而是通过轻量 diff 把**新增/改写的关键词与短语**用浅黄/浅青 `<mark>` 高亮，下方用极简灰字展示「改动原因 + 命中的 JD 要求标签（如 `核心能力` / `硬性要求`）」；
  - 顶部新增紧凑的 **JD 四类要求概览条**（硬性要求 / 核心能力 / 加分项 / 其他），点击右栏任意经历仍支持直接行内编辑、还原原句与确认保存导出 `.docx`。

## 3. AI 助手前端改造：顶部快捷区随对话自然滚动（不要固定吸顶）

- **修改文件**：`web/assets/js/views/assistant.js`、`web/assets/app.css`
- **具体改造**：
  1. 将 `.tn-assistant-welcome`（问候语、状态胶囊、求职画像已建立/未建立条、4 张快捷任务卡）**移入 `.tn-assistant-thread` 滚动容器内部的最顶部**，作为对话流的第一块普通文档流元素（**严禁使用 `position: sticky` 或放在滚动容器外面**）；
  2. 这样效果完全符合预期：
     - 打开新会话时，顶部完整展示欢迎区、画像条和 4 张快捷卡；
     - 随着对话增多向下滚动，欢迎区自然滚出视口，**对话消息区独享完整阅读空间**；
     - 用户随时向上滑动回到顶部，依然能看到并点击 4 张快捷任务卡或 `[修改画像]`；
  3. 同步确保点击快捷提示词或发送消息后，滚动位置平滑锚定在最新消息底部，不跳回顶部。
