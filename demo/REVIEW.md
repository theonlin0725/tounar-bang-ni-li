# 帮你理 · 交互设计 demo 评审导览

> 状态：**设计演示，未进入开发。** 本目录只有静态 HTML/CSS/JS，不连接任何服务，不写入任何存储。
> 目的：在写生产代码前，把 PRD 的页面、状态和文案纪律先跑一遍，供产品 / 设计 / 前端一起拍板。

打开方式：双击 `demo/index.html`，或在本目录运行 `python3 -m http.server 8000` 后访问
`http://localhost:8000`。

## 1. 五分钟评审路线

| 顺序 | 看什么 | 重点检查 |
|---|---|---|
| 1 | 登录页 | 英文 slogan + 中文副标；邮箱验证码；错误与内测拒绝不闪台账 |
| 2 | 投递台账 | 三统计 + 单页台账；「已投天数刻度尺」是否把「等了多久 / 该不该回看」讲清楚 |
| 3 | 点任意一行 | 详情抽屉：来源、时间、JD、链接、状态时间线；纠错留痕；终态与归档的差异 |
| 4 | 待确认 → 任一项 | 复核抽屉：证据、候选、409、D12 阻塞；采纳前后会发生什么 |
| 5 | 提醒设置 / 数据与授权 | 发什么 / 不发什么；邮箱与插件是两项独立授权；删除是异步任务 |

| 7 | 提醒邮件预览 / 落地页 | 预取不写入；明确点击后 ready 才提交；completed 只恢复结果 |

## 2. 页面与状态清单

### 2.1 登录前

- 品牌主张、产品说明、样张台账（明确标注「样张 · 演示数据」）。
- 邮箱 → 6 位验证码两步；倒计时、重发、改邮箱。
- 验证码错误 / 过期提示；内测未准入时中性拒绝，不渲染上一用户台账。
- 演示规则：任意 6 位数字通过，`000000` 报错，`demo@blocked.com` 触发内测拒绝。

### 2.2 投递台账（单页）

- 三统计：累计投递 18 / 进行中 11 / 面试中 3；全量口径，不随筛选变化。
- 四个入口：已投递明细、看过没投、待确认、已归档。
- 搜索、状态筛选、来源筛选、待回看筛选；结果数与全量数分开显示。
- 表格列：公司 / 岗位 / JD 摘要 / 渠道 / 状态 / 已投天数 / 投递链接 / 查看状态 / 更新时间。
- 已投天数刻度尺：0–30 天细线、14 天回看线、当前天数圆点；到期显示「该回看 · 超线 N 天」。
- 终态与归档分别表达：终态不再自动更新；归档不等于拒绝，累计投递不减少。

### 2.3 异常与空状态（对应前端 PRD 7.2）

| 状态 | demo 呈现 |
|---|---|
| 首次加载 | 骨架屏 + 「首次同步中」，不显示 0，不宣称无更新 |
| 新用户零数据 | 「还没有投递记录」+ 装插件 / 连邮箱 / 补录（次要） |
| 筛选无结果 | 「没有符合筛选的记录」+ 清空筛选；不写「尚未投递」 |
| 有浏览无投递 | 主表为空，看过没投入口单独计数 |
| 首次同步中 | 首扫范围、126 / 约 400 封、逐条归入台账 |
| 邮箱失效 | 顶部警示 + 重新授权；不静默吞错、不删历史 |
| 插件最近未联系 | 最近心跳、6 天前、排查建议；不把心跳当卸载结论 |
| 旧数据刷新失败 | 「当前显示的是 10-20 08:00 的快照」+ 重试 |
| 503 / 云不可用 | 明确「数据暂不可用」，三统计为「—」，不回退 localStorage 假成功 |
| 409 并发修改 | 复核抽屉内模拟；重取最新版本，要求重新决定，不自动覆盖 |
| 保存中 / 删除中 | 禁用重复提交，显示任务状态；202 只代表已受理 |
| 无安全链接 / 时间未知 | 明确缺失原因与纠错路径；不拼 URL、不补造日期 |
| 删除部分完成 | 云端已完成、备份等待到期、设备待确认，分 scope 展示 |

### 2.4 抽屉与弹窗

- **记录详情**：来源与时间、JD 摘要、安全外链、状态时间线、最近确认；进行中 / 终态 / 已归档三套操作。
- **纠错**：原因必填；写入历史，不伪装成自动识别；终态纠错标注 D05 待冻结。
- **确认状态无变化**：同日重复点击不重复计时；成功后更新「最近确认」。
- **复核队列**：疑似提交、邮件多候选、状态冲突、终态候选、历史申请未知时间（D12 阻塞）。
  含候选选择、可信投递日期、采纳影响说明、忽略、409 重取。
- **兜底补录**：手动录入 / 粘贴链接或 JD / 截图识别（禁用并说明 D09 未冻结）。
  缺时间转待确认，不默认今天；重复命中进入复核，不强合并。
- **提醒设置**：发什么 / 待回看频率 / 不发什么；保存失败保留旧值。
- **数据与授权**：插件与 QQ 邮箱分区；设备解绑后的服务端撤销、设备清理 unknown / acknowledged 分开显示。
- **QQ 邮箱授权向导**：授权范围 → 连接信息 → 再次确认 → 连接中 → 结果；授权码不落本地。
- **断开邮箱 / 解绑设备 / 删除数据**：二次确认；删除输入「删除」；异步任务含运行中 / 部分完成 / 失败 / 全部完成。
- **提醒邮件预览**：A 类状态变化 + B 类待回看；无内容时 0 封；不做日报。
- **安全落地页**：预取 0 写入；明确点击后创建一次性资格；`done` 只恢复结果，不重复计时。
- **演示控制面板**：页面、场景、删除结果、预取、设备回执、动作日志。

## 3. 关键设计取舍

1. **单页台账，不做分析大屏。** 三统计只回答「投了多少 / 还在进行多少 / 面到多少」，
   其余信息留在行内和详情里，避免把追踪工具做成报表工具。
2. **「已投天数刻度尺」是核心识别元素。** 同一根 0–30 天线同时表达已投天数、回看线和是否到期，
   比单独一个数字更能回答「这条要不要管」。
3. **纸质台账的冷静感。** 冷纸色、宋体标题、细分隔线、低饱和状态色；状态色只做辅助，
   文字标签始终存在，满足「状态不只靠颜色」。
4. **异常状态是主路径，不是边角。** 首次同步、邮箱失效、插件离线、旧快照、503、409、删除异步
   都有独立呈现和明确禁止文案；演示数据全部带「演示数据 / 设计演示」标记。
5. **授权与删除讲边界。** 不用网页按钮假装能改 Chrome 权限；不把 202 当完成；
   不把「云端完成」写成「所有设备已清除」。
6. **文案克制。** 不写「已同步全部」；不写「今日无更新」；不写安慰性内容；
   缺失字段显示缺失，不用假值填充。

## 4. 演示边界（评审时请按此理解）

- 纯静态页面，**无网络请求、无后端、无持久化**；刷新即重置，所有操作只改内存。
- 邮件、插件、官网状态、删除任务、设备回执均为**模拟**；演示面板和动作日志会标明。
- 外链按钮只提示「演示环境不打开外部链接」，不真正跳转。
- OTP、409、202、设备清理回执等用固定演示规则触发，不代表真实服务时序。
- 页面是桌面优先（1280 / 1440）；窄窗口下表格在容器内横向滚动，不承诺移动端生产适配。
- 演示时钟固定为 2026-10-21 10:42，台账数据截至 08:00；「今天」不随系统日期变化，避免评审时数字漂移。

## 6. 需要产品拍板的 D 项（demo 的临时处理）

| 编号 | 问题 | demo 当前处理 |
|---|---|---|
| D01 | 「停留 3 秒算看过」的准确定义 | 文案按「详情页可见累计 ≥3 秒；列表页不记录」展示，规则未冻结 |
| D05 | 终态自动锁定后，用户纠错如何恢复 | 终态锁定，但保留「纠错状态 + 原因」并留痕；面板标注待冻结 |
| D06 | 每日 / 周一、同岗 7 天频控、A 类新线索范围 | 设置里解释「每日 = 每天评估新到期，同岗最多 7 天一次」，并标注 D06 待冻结 |
| D09 | 首扫范围、正文保留、OCR / 外发 | 近 30 天 + 默认不保留正文；截图识别禁用并说明原因 |
| D11 | 08:00 送达与 ≤24h 时效 | 文案写「准点送达承诺以 D11 为准」，不做硬承诺 |
| D12 | JD / 链接 / 投递时间缺失能否入账 | 未知时间转待确认，不补造日期；复核项明确标注 D12 未冻结 |
| D13 | 「+ 归档线索」命名与备注字段 | 保留原名并加副说明「补录漏采岗位」；不做无法保存的备注框 |
| D03 / D04 | 归档、去重规则 | 归档不删除、不减少累计；疑似重复进复核，不前端强合并 |

这些项建议在开发前统一冻结，尤其是 D05、D06、D12、D13——它们会同时影响状态机、接口字段和文案。
